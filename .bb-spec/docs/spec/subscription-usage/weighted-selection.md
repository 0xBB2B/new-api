# 订阅渠道用量加权选择

## 目的

让同一候选层内多个订阅渠道的被选概率随剩余额度动态调整，长期收敛到各账号用量窗口使用率均匀。

## 逻辑

渠道选择的层内加权随机阶段，订阅渠道（type 57 Codex、type 61 Claude Subscription）的瓶颈使用率读自渠道用量缓存。其有效权重在现行等效权重（静态 weight 经整数平滑后的值）基础上乘以剩余比例 `(100 − 瓶颈使用率)/100`。使用率越高被选概率越低；其他类型渠道的权重完全不受影响。

## 约束

- 动态缩放仅作用于订阅渠道（type 57、type 61）；同层其他类型渠道沿用现行静态等效权重，混合参与同一次加权随机。
- 缩放基数是现行整数平滑后的等效权重（含全零补偿、小权重放大），不是原始 weight 字段值；缩放结果向下取整后最小为 1，保证未触顶渠道始终可被选中。
- 渠道用量缓存缺失或已过期（距最近成功刷新超过 10 分钟）时，该渠道不做动态权重缩放，回退为现行静态等效权重参与选择。缓存过期窗口与触顶移出的短期保护共用同一时间窗，保证轮询临时失败时最近已知的高使用率数据仍参与打折，而非跳变回未打折权重。
- 优先级分层、失败重试降级到下一优先级、`auto` 跨分组等选择语义不变；动态缩放只发生在层内加权随机这一步。
- 本机制不引入新的持久化字段，不修改渠道 Status。

## 例子

同一优先级层内有三个渠道：Codex 渠道 A（静态等效权重 100，缓存瓶颈使用率 60，最近 8 分钟内成功刷新）、Claude 订阅渠道 B（静态等效权重 100，缓存距最近成功刷新已超过 10 分钟）、普通 OpenAI 渠道 C（静态等效权重 100）。计算：A 的有效权重 = 100×0.4 = 40；B 回退静态 = 100；C 不受影响 = 100。三者以 40:100:100 加权随机，A 的被选概率约 16.7%。

另一个例子体现过期窗口内的保护：Claude 订阅渠道 D（静态等效权重 100，缓存瓶颈使用率 90，最近成功刷新在 8 分钟前，其后上游用量接口连续失败）。D 的有效权重 = 100×0.10 = 10（下取整仍 ≥1），仍按已知高使用率打折，不因刷新失败就跳回未打折权重。

## 验收

- [ ] 两个订阅渠道静态权重相同、缓存瓶颈使用率分别为 20 与 80 时，有效权重之比为 80:20。
- [ ] Codex 渠道与 Claude 订阅渠道在缓存瓶颈使用率相同、静态权重相同时有效权重相等。
- [ ] 缓存过期（距最近成功刷新超过 10 分钟）的订阅渠道有效权重等于其静态等效权重。
- [ ] 最近成功刷新在 6 分钟前、缓存瓶颈使用率 90 的订阅渠道有效权重 = 静态等效权重 × 0.10（下取整 ≥1），不回退静态。
- [ ] 同层非订阅渠道的权重在机制启用前后完全一致。
- [ ] 瓶颈使用率 94 且静态等效权重较小时，有效权重向下取整后仍 ≥1。
- [ ] 优先级降级顺序与 retry 行为和机制引入前一致。

# 点用量区域打开用量弹窗

## 目的
渠道列表的余额列横向空间有限。订阅渠道（Codex、Claude 订阅）右侧的「账户信息」按钮只是弹窗入口，去掉它，把用量区域本身当入口，省出一个按钮的宽度。

## 逻辑
- 适用渠道：Codex（type 57）与 Claude 订阅渠道的非标签行。普通渠道的已用/余额徽章、标签行、vLLM / SGLang 渠道的状态徽章都不变。
- 余额列只渲染一个入口，不再渲染「账户信息」按钮：
  - 敏感信息可见、有用量快照 → 用量进度条（5h / 7d 行）整块是入口；
  - 敏感信息可见、无快照 → `-` 是入口；
  - 敏感信息隐藏 → 一个打码徽章 `••••` 是入口，不显示进度条。
- 点击入口：Codex 渠道请求 Codex 用量接口，成功后打开 Codex 用量弹窗；Claude 订阅渠道请求 Claude 用量接口，成功后打开 Claude 用量弹窗。失败时按现有方式弹错误提示，不打开弹窗。
- 请求进行中：入口整块透明度降低、鼠标显示为等待状态，`aria-busy=true`；此时再点击不发新请求。
- 入口是可聚焦的按钮语义（`role=button`、`tabIndex=0`），聚焦后按回车或空格等同于点击。
- 每个窗口行原有的悬浮提示（「将于 <时间> 重置」/「暂未开始计时」）保留；隐藏敏感信息时的打码徽章没有悬浮提示。

## 约束
- 订阅渠道的余额列不出现「账户信息」文字。
- 一次点击最多触发一次用量请求；请求未结束前重复点击不产生新请求。
- Codex 渠道的入口永远打开 Codex 弹窗，Claude 订阅渠道的入口永远打开 Claude 弹窗。
- 键盘回车、空格与鼠标点击行为一致。

## 例子
- Claude 订阅渠道 #12，快照 5 小时 13%、每周 17% → 余额列只显示两行进度条；点击后调用 `GET /api/channel/12/claude/usage`，成功后打开「Claude 账号与用量」弹窗。
- Codex 渠道 #7，无快照 → 余额列显示 `-`；点击后调用 `GET /api/channel/7/codex/usage`，成功后打开「Codex 账户和用量」弹窗。
- 隐藏敏感信息时的 Claude 订阅渠道 → 余额列显示 `••••`；点击后同样打开 Claude 弹窗。
- 用户在请求返回前连点三次 → 只发出一次请求。
- Tab 聚焦到 Codex 渠道的进度条后按回车 → 与点击相同。

## 验收
- [ ] 订阅渠道的余额列不再渲染「账户信息」按钮。
- [ ] 有快照、无快照（`-`）、隐藏敏感信息（`••••`）三种入口点击都会请求对应接口并打开对应弹窗。
- [ ] 请求进行中入口变淡且 `aria-busy=true`，重复点击不发新请求。
- [ ] 入口可以用 Tab 聚焦，回车和空格都能触发。
- [ ] 普通渠道、标签行、vLLM / SGLang 渠道的余额列渲染与交互不变。

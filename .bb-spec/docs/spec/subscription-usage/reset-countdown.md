# 用量窗口重置倒计时

## 目的
让 Codex 与 Claude 订阅渠道的用量弹窗都能显示"还有多久重置"。上游只有 Codex 实时接口给相对秒数，Claude 接口和落库快照都只有绝对重置时刻，且快照最多每小时刷新一次，落库时算好的相对秒数展示时已过期。以绝对时刻为唯一来源、渲染时现算，两种渠道一次修好。每周窗口的剩余时长常常超过 100 小时，只按小时显示读起来费劲，超过一天时拆成天、小时、分钟。

## 逻辑
- 适用范围：渠道用量弹窗中的 5 小时窗口卡片与每周窗口卡片的「将于以下时间重置」一栏。「重置于」一栏继续显示 `reset_at` 对应的绝对时间，不受本规则影响。
- 数据来源：窗口对象的 `reset_at`（Unix 秒）。`reset_after_seconds` 之类的相对秒数字段一律不读取，窗口类型定义中也不再保留该字段。
- 派生规则：剩余秒数 = `reset_at` − 当前时间（秒），取整数。
- 显示：
  - `reset_at` 缺失、非数字或 ≤ 0 → 显示 `-`。
  - 剩余秒数 ≤ 0（重置时刻已过）→ 显示 `-`。
  - 剩余秒数 > 0 → 按时长格式显示：≥ 1 天为 `Nd Hh Mm`，≥ 1 小时不足 1 天为 `Nh Mm`，不足 1 小时为 `Mm Ss`，不足 1 分钟为 `Ss`。各段单位走 i18n（中文为 天 / 小时 / 分钟 / 秒），中间段为 0 时仍显示（如 `7d 0h 0m`）。
- 时长格式是订阅用量共享的格式化函数，同一卡片的「窗口:」一栏（`limit_window_seconds`）也用它显示，因此每周窗口的「窗口:」显示 `7d 0h 0m` 而非 `168h 0m`。
- 当前时间取渲染时刻，同一次渲染内两个窗口使用同一个当前时间。

## 约束
- 派生逻辑放在订阅用量的共享解析模块中，以纯函数形式接收窗口对象与当前时间，便于确定性测试；卡片组件只负责调用与展示。
- 时长格式化只在共享解析模块里实现一份；其他弹窗字段（如 Codex 凭据剩余有效期）需要天级显示时直接调用它，不得在调用方另写一套按天拆分的逻辑。
- 不改变窗口归类、百分比夹取、颜色分级、「重置于」格式化的现有逻辑。
- 不引入定时器自动刷新倒计时；用户重新打开弹窗或点刷新时自然重算。

## 例子
- 窗口 `{ reset_at: 1700360000 }`，当前时间 1700000000 → 剩余 360000 秒（100 小时），显示 `4d 4h 0m`。
- 窗口 `{ reset_at: 1700090000 }`，当前时间 1700000000 → 剩余 90000 秒，显示 `1d 1h 0m`。
- 窗口 `{ reset_at: 1700086399 }`，当前时间 1700000000 → 剩余 86399 秒，显示 `23h 59m`。
- 窗口 `{ reset_at: 1700003600 }`，当前时间 1700000000 → 剩余 3600 秒，显示 `1h 0m`。
- 窗口 `{ reset_at: 1700000090 }`，当前时间 1700000000 → 剩余 90 秒，显示 `1m 30s`。
- 窗口 `{ reset_at: 1700000045 }`，当前时间 1700000000 → 剩余 45 秒，显示 `45s`。
- 窗口 `{ reset_at: 1699999000 }`，当前时间 1700000000 → 已过重置时刻，显示 `-`。
- 窗口 `{ used_percent: 0, limit_window_seconds: 18000 }`（无 `reset_at`，Claude 5 小时窗口无用量时的形态）→ 显示 `-`。
- 窗口 `{ reset_at: 1700003600, reset_after_seconds: 99 }`，当前时间 1700000000 → 显示 `1h 0m`，相对秒数字段被忽略。
- 窗口 `{ limit_window_seconds: 604800 }` → 「窗口:」一栏显示 `7d 0h 0m`。

## 验收
- [ ] Claude 订阅渠道弹窗的每周窗口卡片在有 `reset_at` 且剩余超过一天时显示 `Nd Hh Mm`，不再出现 `100h` 这类超过 24 的小时数。
- [ ] Claude 5 小时窗口无 `reset_at` 时「重置于」与「将于以下时间重置」均为 `-`。
- [ ] Codex 渠道弹窗在仅有 `reset_at`、没有相对秒数字段的快照上同样显示剩余时长。
- [ ] 重置时刻已过的窗口显示 `-`，不出现负数或 `0s`。

# Codex 渠道触顶移出与回归

## 目的

防止把请求继续分发给额度即将耗尽的 Codex 订阅账号，避免上游 429 与无谓重试。

## 逻辑

Codex 渠道（type 57）的瓶颈窗口使用率 `max(5h used_percent, 7d used_percent) ≥ 95` 即为触顶。触顶渠道在渠道选择时被移出候选集，不参与层内加权随机；后续轮询发现使用率回落到 95 以下（窗口重置）后自动恢复参与。若最近一次成功刷新显示触顶，之后轮询或同步持续失败导致条目过期，该渠道在最近触顶后的 10 分钟内仍视为触顶；超过 10 分钟仍无新成功刷新时，按过期缓存处理。触顶是纯选择层的临时过滤，不改变渠道任何持久化状态。

## 约束

- 触顶阈值固定 95（百分比），判定数据源为渠道用量缓存；缓存缺失的渠道不判定触顶。
- 未曾触顶的过期缓存不判定触顶；曾触顶渠道在最近触顶后的 10 分钟内，即便上游刷新持续失败导致条目过期，也继续从候选中移出。
- 触顶不修改渠道 Status，不触发 auto-ban，不写数据库；管理端渠道列表中该渠道仍显示为启用。
- 某层全部 Codex 渠道触顶时：层内还有其他渠道则在其余渠道中选择；整层无可用渠道则按既有重试语义降级到下一优先级。
- 渠道亲和缓存命中的目标渠道若已触顶，本次跳过亲和粘滞，改走正常选择流程；亲和缓存本身不清除。
- 渠道从未触顶变为触顶、从触顶回归时，各记录一条服务端系统日志（含渠道 ID 与当时使用率）。

## 例子

Codex 渠道 A 缓存为 (5h=96.2, 7d=40)，瓶颈使用率 96.2 ≥ 95，触顶。此后请求选择时 A 不出现在候选中，落到同层渠道 B；某用户的亲和缓存指向 A，其请求同样跳过 A 选中 B。之后 8 分钟内上游 usage 接口连续失败，A 的缓存虽未成功刷新但距离最近触顶未超过 10 分钟，A 仍不参与选择。5 小时窗口重置后，下一轮轮询刷新 A 缓存为 (5h=1.3, 7d=41)，瓶颈使用率 41 < 95，A 自动回到候选集。全过程 A 的 Status 始终为启用，日志中有 A 触顶与回归各一条记录。

## 验收

- [ ] 缓存 (5h=95.0, 7d=10) 的 Codex 渠道不出现在选择候选中；(5h=94.9, 7d=10) 的渠道正常参与。
- [ ] 触顶期间该渠道 Status 保持不变，管理端仍显示启用。
- [ ] 轮询刷新后使用率回落至 95 以下，无需任何人工操作渠道即恢复参与选择。
- [ ] 亲和命中的目标渠道触顶时，请求被分发到其他渠道而非粘滞目标。
- [ ] 从未触顶或最近未触顶的过期缓存不被移出（回退静态权重参与）。
- [ ] 曾触顶渠道在最近触顶后 10 分钟内刷新失败并过期时仍被移出；超过 10 分钟仍无新成功刷新时不再移出。
- [ ] 触顶与回归各产生一条含渠道 ID 与使用率的系统日志。

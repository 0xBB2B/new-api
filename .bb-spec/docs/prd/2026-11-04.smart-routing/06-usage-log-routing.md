# 日志中的路由信息

## 用户故事
### P0：作为员工，我想在使用日志里看到每次请求被分到了哪一档、为什么，以便明白自己的钱花在了哪里

**用例（主路径）**
- 场景：小王的一次 auto-gpt 请求被分到困难档，由 gpt-5.6-sol 回答。
- 操作：打开使用日志。
- 预期：这条记录的模型列显示 gpt-5.6-sol，下面小字写"auto-gpt · 困难档"；它下面紧挨着一条模型为打分模型、小字写"路由打分 · auto-gpt"的记录。打开详情，「请求转换」下面有「智能路由」一块，写着虚拟模型、档位、选档原因、打分标签和"查看这次打分"。

### P0：作为管理员，我想按档位和原因统计路由效果，以便以后调整规则

**用例（主路径）**
- 场景：管理员查看一段时间的使用日志。
- 操作：逐条看主请求的详情。
- 预期：每条路由请求都记着虚拟模型、档位、命中的规则和各项打分标签，打分记录和主请求用同一个请求 ID。

## 约束
- C1：日志列表里，经过智能路由的主请求，模型列照旧显示真实模型，下面加一行小字：
  - 普通情况 → "<虚拟模型> · <档位>"，灰字；
  - 交给顾问 → "<虚拟模型> · 顾问"，黄字；
  - 打分失败 → "<虚拟模型> · <档位> · 打分失败"，红字。
- C2：打分记录在日志列表里单独一行：模型列显示打分模型，下面小字"路由打分 · <虚拟模型>"，灰字。
- C3：主请求的详情弹窗在「请求转换」下面新增「智能路由」一块，写法和「Token 明细」等块相同，按顺序显示：
  - 虚拟模型；
  - 档位：降档被拦时写"<实际档位>（打分结果：<打分档位>）"；打分失败用了默认档时写"<档位>（默认档）"；
  - 选档原因；
  - 打分标签：依次是任务类型、要想多深、工作量、出错代价、工作类型、把握、用户反馈；
  - 思考内容：只在清理了思考内容时显示"上一轮用的渠道不同，已清理 X 段"；
  - 打分记录：打分成功时是"查看这次打分"链接，点了打开对应打分记录的详情；打分失败时写"没有拿到用量，没有扣费"。
- C4：选档原因的写法：
  - 命中的规则，例如"出错代价=高"；
  - 降档被拦时，例如"对话历史 86,420 token，超过降档上限 20,000，保留上一轮的困难档"；
  - 交给顾问时写"用户连续 X 条消息不满意"；
  - 打分失败时写失败原因，例如"打分超时（2000 毫秒），使用默认档"，红字；
  - 工具结果续跑时写"工具结果续跑，沿用上一轮的档位"。续跑请求的详情里没有打分标签和打分记录这两行。
- C5：打分记录的详情弹窗里，「智能路由」一块显示：
  - 类型"路由打分"；
  - 虚拟模型；
  - 属于请求：主请求的请求 ID，以及它的档位和模型。点击打开主请求的详情。
- C6：用户和管理员看到的路由信息相同；路由信息里不包含任何对话内容。
- C7：日志里没有经过智能路由的请求，显示和现在完全一样。
- C8：新增的文字都有七种界面语言的翻译。

## 验收
- [ ] C1：分别产生普通、顾问、打分失败三种路由请求 → 列表小字的文字和颜色与预览一致。
- [ ] C2：打分成功的请求 → 列表里有一条打分记录，小字为"路由打分 · auto-gpt"，请求 ID 与主请求相同。
- [ ] C3：打开普通路由请求的详情 → 「智能路由」一块在「请求转换」下面，各行的顺序和内容与预览一致；点"查看这次打分"打开打分记录的详情。
- [ ] C4：降档被拦、交给顾问、打分失败、工具结果续跑四种请求的详情 → 选档原因的文字与 C4 一致；续跑请求没有打分标签和打分记录两行。
- [ ] C5：打分记录详情 → 显示类型、虚拟模型、属于请求；点击后打开主请求详情。
- [ ] C6：普通用户查看自己的日志 → 路由信息和管理员看到的一样，且不含对话文字。
- [ ] C7：直接请求真实模型的日志 → 列表和详情与改动前一致。
- [ ] C8：七种界面语言下，新增文字都有翻译。

## 验证路径
1. 通过 auto-gpt 各产生一条普通路由、降档被拦、交给顾问、打分失败、工具结果续跑的请求。
2. 打开使用日志 → 逐条核对列表小字和详情里的「智能路由」一块，与确认过的预览一致。
3. 从主请求详情点进打分记录，再从打分记录点回主请求 → 两条记录互相能找到。

# 智能路由配置页

## 用户故事
### P0：作为管理员，我想在后台用表单配置虚拟模型，以便不用手写配置、也不会把模型名打错

**用例（主路径）**
- 场景：管理员打开「系统设置 → 请求策略 → 智能路由」。
- 操作：点「添加虚拟模型」，名称填 auto-gpt，三档分别选 gpt-5.4-mini、gpt-5.5、gpt-5.6-sol 并排好分组顺序，选好打分模型和顾问，点弹窗里的「保存」，再点页面右上角「保存更改」。
- 预期：弹窗关闭，表格里多出 auto-gpt 一行，接口列显示 Responses；之后用户请求 auto-gpt 按新配置路由。

**用例（边界 / 异常）**
- 场景：困难档选了 gpt-5.6-sol，分组顺序里有 api，但 api 分组没有 gpt-5.6-sol 的可用渠道。
- 操作：点弹窗里的「保存」。
- 预期：弹窗不关闭，困难档模型下面用红字写"gpt-5.6-sol 在分组 api 里没有可用渠道"。
- 场景：名称填了 gpt-5.5。
- 预期：名称下面红字写"gpt-5.5 是真实模型名，虚拟模型不能和真实模型重名"。

## 约束
- C1：入口：「系统设置 → 请求策略」左侧菜单在「渠道健康」后面新增「智能路由」；能看到其他请求策略分区的人才能看到它。
- C2：页面标题「智能路由」，右上角「保存更改」。正文是一张「虚拟模型」卡片：
  - 标题后面显示虚拟模型的数量；
  - 说明文字"每个虚拟模型配好三档模型、打分模型和顾问。用户在客户端里把模型名填成虚拟模型名就能用。"；
  - 「可视化 / JSON」切换和「添加虚拟模型」按钮；
  - 表格。

  这张卡片的写法和「会话与重试」里的「会话规则」相同。
- C3：表格一行一个虚拟模型，列依次是：名称、简单档、普通档、困难档、打分模型、顾问、操作。
  - 名称列：第一行是虚拟模型名，第二行是"<接口> 接口"。
  - 三个档位列：第一行是模型名，默认档后面带「默认」标签；第二行是"分组顺序（用 → 连接）· 思考力度"。
  - 打分模型列：第二行是"分组顺序 · 超时 X 毫秒"。
  - 顾问列：第二行是"连续 N 次不满意"。
  - 操作列：编辑图标，以及一个「…」菜单，菜单里有「删除」，删除前先弹确认框。
- C4：还没有虚拟模型时，卡片里显示空状态：标题"还没有虚拟模型"，说明"添加一个虚拟模型，比如 auto-gpt。用户在客户端里把模型名填成它就能用。"，下面一个「添加虚拟模型」按钮。
- C5：点「添加虚拟模型」或编辑图标，打开「添加虚拟模型」或「编辑虚拟模型」弹窗，写法和「编辑规则」弹窗相同，内容从上到下依次是：
  1. 名称（必填）和接口。接口只读，按所选模型自动判断，没选模型时提示"选好模型后自动判断"。
  2. 「档位」：简单档、普通档、困难档各一块，每块有模型下拉、思考力度下拉（不覆盖 / low / medium / high，默认"不覆盖"）和分组顺序；最后是默认档下拉，默认选普通档。
  3. 「打分模型」：模型下拉、超时（毫秒，默认 2000）、分组顺序。
  4. 「顾问」：模型下拉、连续不满意几次后交给顾问（默认 2）、分组顺序。
  5. 「高级设置」折叠区：降档时历史 token 上限（默认 20000）、可信度门槛（默认 0.6）、简单题消息长度上限（字，默认 2000）。

  底部是「取消」和「保存」。
- C6：模型下拉里只列出至少在一个分组里有可用渠道的模型。分组顺序用创建 API 密钥时的「自动分组顺序」组件（添加分组、拖动排序、上移、下移、删除）。
- C7：点弹窗里的「保存」时由后台逐项检查。有问题时弹窗不关闭，在出错的字段下面用红字写原因；全部通过才关闭弹窗、更新表格。检查项和提示文字如下：
  - 名称为空 → "请填写名称"；
  - 名称和真实模型重名 → "<名称> 是真实模型名，虚拟模型不能和真实模型重名"；
  - 名称和其他虚拟模型重名 → "已经有叫 <名称> 的虚拟模型"；
  - 三档、打分模型、顾问的模型没选 → "请选择模型"；
  - 分组顺序为空 → "至少选择一个分组"；
  - 模型在所配的某个分组里没有可用渠道 → "<模型> 在分组 <分组> 里没有可用渠道"；
  - 模型没有设置价格 → "<模型> 还没有设置价格，请先到「模型定价」里设置"；
  - 三档和顾问的模型接口不一致 → "<模型> 只支持 <接口>，这个虚拟模型的其他模型走 <接口>"（打分模型不要求接口一致）；
  - 数字超出范围 → 写明允许的范围。范围是：超时 100~30000 毫秒；连续不满意次数 1~10；降档上限 ≥ 0 的整数；可信度门槛 0~1；简单题消息长度上限 1~100000。
- C8：弹窗保存后，要点页面右上角「保存更改」配置才生效，和这一页其他分区一样。没有改动时点「保存更改」，提示"没有需要保存的更改"。
- C9：「JSON」视图显示同一份配置，可以直接编辑，保存时按 C7 同样检查。
- C10：页面里所有新增文字都有 en、zh、zh-TW、fr、ru、ja、vi 七种语言的翻译。

## 验收
- [ ] C1：管理员在请求策略菜单里看到「智能路由」，位于「渠道健康」之后；没有请求策略权限的账号看不到。
- [ ] C2：页面标题、卡片标题与数量、说明文字、切换按钮、「添加虚拟模型」按钮都和确认过的预览一致。
- [ ] C3：配置 auto-gpt 后，表格这一行各列的两行文字和预览一致，默认档带「默认」标签；从「…」菜单删除时先弹确认框，确认后这一行消失。
- [ ] C4：删光虚拟模型 → 显示空状态的标题、说明和按钮，点按钮打开添加弹窗。
- [ ] C5：打开添加弹窗 → 各项默认值是：思考力度"不覆盖"、默认档"普通档"、超时 2000、连续不满意次数 2、降档上限 20000、可信度门槛 0.6、简单题长度上限 2000；接口提示"选好模型后自动判断"。打开编辑弹窗 → 各项显示已保存的值。
- [ ] C6：某个模型在所有分组都没有可用渠道 → 下拉里没有它；分组顺序可以添加、拖动、上移、下移、删除。
- [ ] C7：逐条构造 C7 列出的每一种错误 → 对应字段下面出现对应的红字，弹窗不关闭；全部改正后保存 → 弹窗关闭，表格更新。
- [ ] C8：弹窗保存后不点「保存更改」就刷新页面 → 改动不生效；点了 → 生效。没有改动时点「保存更改」→ 提示"没有需要保存的更改"。
- [ ] C9：在 JSON 视图里把困难档模型改成没有渠道的模型再保存 → 报同样的错误。
- [ ] C10：切换到七种界面语言 → 新增文字都有对应翻译，没有显示成英文原文或翻译键。

## 验证路径
1. 管理员打开智能路由页 → 看到空状态 → 添加 auto-gpt 并保存更改 → 表格出现这一行。
2. 编辑 auto-gpt，困难档换成在 api 分组没有渠道的模型，点保存 → 出现红字，弹窗不关。
3. 改回来保存、保存更改 → 用户请求 auto-gpt 按新配置路由。
4. 拿实际页面和确认过的预览逐项对比：布局、文案、空状态、弹窗、报错。

# 顾问升档

## 用户故事
### P1：作为员工，我希望连续几次答得不好之后能自动换最强的模型来答，以便不用自己去切模型

**用例（主路径）**
- 场景：auto-chat 的顾问是 gpt-5.6-sol，分组顺序 subscription，连续不满意次数是 2。
- 操作：运营小张先说"写得不对，重写"，下一条又说"还是不行"。
- 预期：第二条消息由 gpt-5.6-sol 在 subscription 分组回答；日志里档位显示"顾问"，原因写"用户连续 2 条消息不满意"。

**用例（边界 / 异常）**
- 场景：顾问回答后，小张接着说"还是不对"。
- 预期：连续不满意变成 3 条，仍由顾问回答。
- 场景：顾问回答后，小张说"好了，谢谢"。
- 预期：恢复按打分选档；降档保护拿顾问之前的那一档来比较。
- 场景：打分失败，判断不了用户满不满意。
- 预期：不交给顾问，用默认档。

## 约束
- C1：每次打分时，给最近 N+1 条用户消息（含最新一条）各贴一个用户反馈标签：满意 / 不满意 / 中性。N 是配置的"连续不满意几次后交给顾问"。
- C2：从最新一条用户消息往前数，连续标为"不满意"的条数 ≥ N → 这一轮交给顾问模型，按顾问配置的分组顺序找渠道（密钥分组是 auto 时，跳过用户无权使用的分组）；日志档位记"顾问"，原因写"用户连续 X 条消息不满意"。这一轮之后的工具结果续跑也用顾问。
- C3：下一条用户新消息照常打分。连续不满意的条数仍 ≥ N 时，继续交给顾问；否则按打分结果选档。
- C4：顾问那一轮不改变会话里的"最近一次不是顾问的档位"，所以之后的降档保护拿顾问之前的那一档来比较；但会更新"上一次请求实际用的渠道"，供清理思考内容时判断。
- C5：打分失败 → 不交给顾问，用默认档。
- C6：顾问没有思考力度这项配置，顾问回答时保留客户端传来的思考力度。
- C7：密钥分组不是 auto → 顾问只在密钥自己的分组里找渠道；找不到可用渠道时不交给顾问，按打分结果选档。

## 验收
- [ ] C1：N=2 时截获打分请求 → 带了最近 3 条用户消息，打分结果里每条都有用户反馈标签。
- [ ] C2：N=2，最近两条用户消息都是不满意 → 由顾问模型回答，日志档位为"顾问"；随后的工具结果续跑也由顾问模型处理。
- [ ] C3：顾问回答后用户又说"不对"→ 仍由顾问回答；用户说"好了"→ 按打分结果选档。
- [ ] C4：顾问之前是普通档，顾问回答后用户发一条简单问题、输入 86,000 token → 用普通档（不是顾问），日志写明降档被拦时比较的是普通档。
- [ ] C5：打分超时，即使用户连续说"不对"→ 用默认档。
- [ ] C6：客户端传思考力度 low，交给顾问 → 上游收到 low。
- [ ] C7：密钥分组固定为 api，顾问模型在 api 分组没有渠道 → 按打分结果选档，不报错。

## 验证路径
1. 在 Chat Completions 客户端里对 auto-chat 连续两次表示不满意 → 第二条由顾问回答，日志档位为"顾问"。
2. 再表示一次不满意 → 仍由顾问回答；表示满意 → 恢复正常档位。

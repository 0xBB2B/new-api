# 用户统计默认看 Token + 数据看板新增利用率分区

## 背景与问题
管理员给员工或客户开通账号后，想知道这些人里有多少真的在用、用得多深，有多少人开了账号却基本不用，以此判断推广效果，决定要不要回收账号或者去催一催。

现在数据看板的「用户统计」只有用量排行和用量趋势，看不出按人数算的比例，管理员只能自己导出数据去数。另外，「用户统计」打开时默认按金额画图，而管理员衡量使用程度时更看重 Token 用量，每次打开都要手动切一次。

## 目标
- 打开「用户统计」时直接看到 Token 用量，不用再手动切换。
- 管理员打开「利用率」分区，就能看到开通用户里深度使用、经常使用、非活跃各有多少人、各占多少比例。

## 非目标
- 不显示每一类具体是哪些用户（不做名单、不能点进去看明细）。
- 不支持自定义阈值（1 亿、100 万）和时间窗（7 天、30 天）。
- 不统计管理员、Root、已禁用、已删除的用户。
- 不改变数据看板开关本身的行为，也不补录开关关闭期间的用量。
- 「用户统计」不记忆上次选的指标。

## 整体验证路径
1. 用管理员账号打开数据看板 → 分区栏依次是 模型调用分析、分流、用户统计、利用率（概览是单独的页面，不在分区栏里）。
2. 点「用户统计」→ 指标切换默认选中「Token」，图表按 Token 用量画；点「金额」→ 图表改按金额画。
3. 点「利用率」→ 显示四张卡片（开通人数、深度使用、经常使用、非活跃）和一条四段比例条，人数和用测试数据算出来的一致。
4. 用普通用户账号打开数据看板 → 分区栏里没有「用户统计」和「利用率」；直接访问利用率数据会被拒绝。

## 决策记录
- **经常使用包含深度使用**：照用户给的截图口径（截图里经常使用 21 = 深度使用 13 + 未达 1 亿的 8）。比例条另外拆出「经常使用（未达 1 亿）」这一段，保证四段之和等于开通人数，没有人被漏算或重复算。否决「三类互斥」：那样三段加起来小于开通人数，占比之和不到 100%。
- **保留「近 30 天超过 100 万、近 7 天未达 100 万」这一段**：用户的文字描述里没有这类人，但截图的比例条里有，用户确认按截图来。
- **开通人数只算启用状态的普通用户**：被禁用的人用不了服务，把他们算进去会让非活跃人数虚高。开通人数同时是所有占比的分母。
- **时间窗按滚动算**：从查看的那一刻往前推 7×24 小时、30×24 小时。否决按自然日：刚过 0 点时「今天」几乎没有数据，数字会突然掉一截，而且结果受时区影响。用户写的是 30 天，截图里的「29 天」不采用。
- **时间窗边界精度 1 小时**：数据看板的用量按「用户 × 模型 × 小时」汇总，每一桶的时间记为该小时的整点。窗口起点落在某个小时中间时，那一桶整桶不计入，所以边界最多少算 1 小时。用户在验收时认可这个精度。否决「起点所在的那一桶也计入」：误差大小不变，只是从少算变成多算；否决改为扫描请求日志：日志表体量大，查询慢。
- **边界**：「超过」按大于算，「不超过」按小于等于算，照用户的原话。
- **Token 只认数据看板记录的输入 + 输出 Token**：按次计费的任务（视频、图片任务等）不产生 Token，只用这类任务的人会被算成非活跃。用户没有提出异议。
- **数据看板开关关闭时照常统计并提示**：利用率的数字完全依赖数据看板记录的用量，开关关着时几乎所有人都会被算成非活跃。用户选择照常显示数字，同时在页面顶部提示「统计不完整」。否决「不提示」：会让管理员误以为大家都不用。
- **提示标题用开关在设置页里的名字**：提示标题为「数据仪表板未开启，统计不完整」，与「系统设置 → 控制台内容 → 数据仪表板」里的开关同名，用户按标题能直接找到开关（用户在交付后确认的修改）。
- **只显示人数、不显示名单**：用户的需求只到统计数字，名单要另外做列表、分页和权限，等真正需要时再做。
- **卡片顺序和比例条对齐**：卡片从左到右依次是开通人数、深度使用、经常使用、非活跃，和比例条的段落顺序一致（用户在确认 HTML 预览时提出）。
- **质疑结论**：值得做。现有「用户统计」只能看排行和趋势，没有按人数算的比例，也没有能直接拿来用的现成功能。

# 顾问的思考力度方式

## 背景与问题
顾问是同一会话里用户连续不满意时临时接手这一轮的模型，一般配的是更强的模型。现在顾问没有自己的力度设置，只能照用客户端发来的思考力度，模型不支持时换成最接近的一档。

2026-11-27 测试服实测：用户在 Claude Code 里关掉思考，客户端发的力度是 none，顾问 gpt-6.2-astra 不支持 none，于是一律换成 low。两次顾问请求的思考需求分一个是 0.6、一个是 0.2，发给上游的力度都是 low。用户连续不满意、最需要认真思考的时候，顾问反而只用最低的思考。

现在唯一的办法是在客户端打开思考或调高力度。但这会同时改变三个档位里设成「不覆盖」的力度，而且客户端只能给一个固定值，做不到按题目难度变化。

## 目标
- 管理员能给顾问设思考力度方式，三种方式和三个档位的完全一样：不覆盖、固定、跟随打分。
- 顾问设成「跟随打分」时，顾问这一轮的力度按打分模型给的思考需求，在管理员配的最低～最高之间、顾问模型支持的档位里按比例选。
- 已有的路由升级后，顾问的行为和升级前一样。

## 非目标
- 不改三个档位和打分模型的力度规则。
- 不改顾问何时接手的规则（连续不满意条数、没有可用渠道时退回其他档位）。
- 不按渠道区分模型能力。
- 不改消费日志详情的显示规则；顾问这一轮的力度沿用档位已有的写法。
- 不改路由编辑窗口里已有的、与顾问力度无关的样式。设计规范里记录的 7 条不达标项照现状保留。

## 依赖与交付顺序
01 → 02。02 保存的设置要由 01 生效；01 的设置可以先用路由 JSON 写入验证。

## 整体验证路径
1. 管理员打开智能路由页，编辑一个顾问是 gpt-6.2-astra（支持 low、medium、high、xhigh、max）的虚拟模型，切到「顾问」标签 → 「思考力度」行显示「不覆盖」选中。
2. 改成「跟随打分」，最低选 medium、最高选 max，保存 → 窗口关闭，弹出「保存成功」；列表「顾问」列第二行写「跟随打分 medium～max · 连续 2 次不满意」。
3. 在 Claude Code 里关掉思考，用这个虚拟模型在同一会话里连续发不满意的消息，直到交给顾问；接手这一轮的消息很难，打分的思考需求是 0.9 → 上游收到的力度是 max；这一轮的工具结果续跑请求，上游收到的力度也是 max。
4. 下一条交给顾问的消息很简单，思考需求是 0.1 → 上游收到的力度是 medium。
5. 打开第 3 步那条请求的消费日志详情 → 「智能路由」块的「思考力度」写「max（跟随打分）」。

## 决策记录
- **顾问也能设力度方式，三种方式和档位完全一样**（用户 2026-11-27 原话："顾问也能设定，然后按照题目难度来动态选择"）：这推翻了已合并 PRD `2026-11-26.advisor-effort-clamp` 非目标里的"不给顾问加思考力度方式配置，顾问仍然以客户端带的力度为准"。当时只想解决上游拒收 none 的 400，没考虑顾问力度和题目难度脱节。被否决的方向：在客户端打开思考。这会同时改变档位里「不覆盖」的力度，而且只能给一个固定值。
- **跟随打分直接用打分模型已经给出的思考需求**：每条用户新消息本来就会打分，交给顾问的那一轮也有分数（测试服日志里顾问请求有 0.6、0.2 的分数）。不需要多调用一次模型，也不增加打分费用。
- **已有路由升级后顾问默认「不覆盖」**（用户 2026-11-27 选定推荐项）：升级不悄悄改变正在运行的路由。被否决的方向：默认「跟随打分」，范围取模型支持的全部档位。这会让思考 token 的花费在管理员不知情时变多。
- **顾问这一轮的工具结果续跑沿用这一轮定下的力度**（用户 2026-11-27 选定推荐项）：和三个档位的规则一样。续跑请求不打分，不沿用的话，「跟随打分」在续跑时拿不到分数，会一律用最高一档；「不覆盖」时同一轮里的续跑也可能因客户端改了力度而前后不一致。被否决的方向：每次续跑都按方式重新算。
- **摘要两处都显示，左侧标签省略时悬停看全文**（用户 2026-11-27 选定）：关掉窗口后也能在列表里看到顾问设了什么力度，和档位列一致。左侧「顾问」标签只有 152px 宽，摘要会被省略，悬停出气泡看全文，和档位小标签的现有做法一样。被否决的方向：标签第二行只写力度、不写模型名。这样会和「打分」标签的写法不一致。
- **顾问列也显示"超出模型能力"的黄字**（用户 2026-11-27 选定）：和档位列一致。否则管理员给顾问设了模型不支持的档位时，列表上看不出实际按哪一档发。
- **界面不达标项照现状保留**（用户 2026-11-27 选定"全记例外"）：顾问这一行要和档位面板完全一致，而这些写法是整个路由编辑窗口共用的，只改顾问这一行做不到。整个窗口一起改和本需求无关，记进设计规范的例外表。
- **质疑结论**：值得做。顾问只在用户连续不满意时出现，正是最需要认真思考的时候；客户端没有办法按难度给力度。

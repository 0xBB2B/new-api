# 顾问这一轮按力度方式定力度

## 用户故事
### P0：作为在 Claude Code 里关掉思考的用户，我想要被交给顾问时，难题能得到更多的思考，以便顾问真的能把我不满意的问题答好

**用例（主路径）**
- 场景：管理员把虚拟模型 auto-gpt 的顾问设成 gpt-6.2-astra（支持 low、medium、high、xhigh、max），力度方式「跟随打分」，最低 medium、最高 max。用户在 Claude Code 里关掉思考（请求带 `thinking.type=disabled`）。
- 操作：用户在同一会话里连续发不满意的消息，直到交给顾问；接手这一轮的消息打分得到思考需求 0.9。
- 预期：发给上游的力度是 max。可选的是 medium、high、xhigh、max 四档，0.9 × 4 = 3.6，取第 4 档。

**用例（工具结果续跑）**
- 场景：同上，顾问这一轮已定为 max。
- 操作：模型调用工具后，客户端把工具结果发回来，接着在这一轮里请求。
- 预期：这次请求不打分，发给上游的力度仍是 max。

**用例（简单题）**
- 场景：同上。
- 操作：下一条交给顾问的消息思考需求是 0.1。
- 预期：发给上游的力度是 medium。

### P0：作为已经在用智能路由的管理员，我想要升级后顾问的行为不变，以便不用担心线上请求的思考花费突然变化

**用例（主路径）**
- 场景：升级前保存的虚拟模型，顾问设置里没有力度方式。
- 操作：升级后，客户端发 `reasoning_effort=high` 的请求被交给顾问 gpt-6.2-astra。
- 预期：发给上游的力度是 high，和升级前一样；客户端发 none 时，发给上游的是 low（不覆盖，由 none 升档）。

### P1：作为管理员，我想要给顾问固定一个力度，以便顾问每次都按我定的力度思考

**用例（主路径）**
- 场景：顾问 gpt-6.2-astra，力度方式「固定」，力度 high。
- 操作：客户端关掉思考，请求被交给顾问。
- 预期：发给上游的力度是 high。

## 约束
- C1 顾问的力度方式三选一：不覆盖、固定、跟随打分。规则和三个档位完全一样：
  - 不覆盖：用客户端发来的力度；客户端没带力度时不加思考参数。
  - 固定：用管理员选的那一档。
  - 跟随打分：在管理员配的最低～最高之间、顾问模型支持的档位里，按思考需求（0～1）乘以可选档位数取对应的一档，结果超出时取最后一档；打分失败或没有思考需求时，取可选档位里最高的一档。
- C2 算出的力度顾问模型不支持时，换成模型支持的档位里最接近的一档，上下一样近取更高的一档；顾问模型不支持思考时，去掉请求里的思考参数。三种方式都按这条处理。
- C3 顾问设置里没有力度方式的路由（升级前保存的），按「不覆盖」处理；发给上游的力度和升级前一样。
- C4 顾问这一轮里的工具结果续跑请求，用这一轮用户新消息定下的力度，不重新计算。
- C5 保存路由时，顾问的力度设置按和档位一样的规则校验，不通过就拒绝保存并指出出错的字段：
  - 「不覆盖」时不能带固定力度或最低、最高力度；
  - 「固定」时必须选一档有效的力度，不能带最低、最高力度；
  - 「跟随打分」时最低、最高都必须是有效的力度，最低不能高于最高，不能带固定力度；
  - 力度方式不是这三种之一时拒绝。
- C6 顾问这一轮的消费日志详情里，「智能路由」块的「思考力度」按档位已有的写法显示力度和来源，例如「max（跟随打分）」「high（固定）」「low（不覆盖，由 none 升档）」。

## 验收
- [ ] C1：顾问「跟随打分」medium～max，思考需求 0.9 → 上游收到 max；思考需求 0.1 → 上游收到 medium；打分失败 → 上游收到 max。
- [ ] C1：顾问「固定」high，客户端带 `thinking.type=disabled` → 上游收到 high。
- [ ] C1：顾问「不覆盖」，客户端带 `reasoning_effort=xhigh` → 上游收到 xhigh；客户端不带力度 → 上游请求里没有思考参数。
- [ ] C2：顾问「固定」none、顾问模型不支持 none → 上游收到 low；顾问模型不支持思考 → 上游请求里没有思考参数。
- [ ] C3：顾问设置没有力度方式字段的路由，客户端发 none、顾问是 gpt-6.2-astra → 上游收到 low，日志写「low（不覆盖，由 none 升档）」。
- [ ] C4：顾问「跟随打分」medium～max，接手这一轮定为 max 后，同一轮的工具结果续跑请求 → 上游收到 max。
- [ ] C5：保存顾问「跟随打分」最低 max、最高 medium → 拒绝，错误指向顾问的最高力度，文案「最低力度不能高于最高力度」；「固定」不选力度 → 拒绝，错误指向顾问的力度；「不覆盖」带最低力度 → 拒绝；力度方式写成 `auto` → 拒绝。
- [ ] C6：顾问「跟随打分」定为 max 的请求，消费日志详情「思考力度」显示「max（跟随打分）」。

## 验证路径
1. 用路由 JSON 把 auto-gpt 的顾问设成「跟随打分」medium～max，保存 → 保存成功。
2. 在同一会话里连续发不满意的消息直到交给顾问，接手的消息打分 0.9 → 上游收到 max；这一轮的工具结果续跑 → 上游收到 max。
3. 再交给顾问一条打分 0.1 的消息 → 上游收到 medium。
4. 把最低改成 max、最高改成 medium 保存 → 拒绝保存，提示最低力度不能高于最高力度。
5. 用升级前保存的路由（顾问没有力度方式字段），客户端关掉思考交给顾问 → 上游收到 low。

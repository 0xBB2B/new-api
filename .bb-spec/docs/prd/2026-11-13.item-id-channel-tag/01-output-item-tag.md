# 所有条目编号带渠道标记

## 用户故事
### P0：作为员工，我希望中台返回的工具调用、消息等条目也记得自己来自哪个渠道，以便之后切模型时中台能认出它们

**用例（主路径）**
- 场景：员工小李在 Codex 里用 deepseek（5 号渠道）做一个任务，上游返回一条思考记录、一条编号 `msg_aaa` 的自定义工具调用（`call_id` 为 `call_1`）和一条编号 `msg_bbb` 的消息。
- 操作：小李收到回答。
- 预期：三条条目的编号都是带标记的字符串，中台读得出渠道 5 和原值；工具调用的 `call_id` 仍是 `call_1`；条目内容不变。

**用例（流式）**
- 场景：同上，Codex 用流式请求。
- 操作：上游依次发条目新增、工具调用参数增量、消息文字增量、条目完成和最终的完整响应。
- 预期：这些事件里出现的同一条条目的编号，全部是同一个带标记的字符串。

## 约束
- C1：Responses 格式的响应里，每条带非空 `id` 的输出条目，返回给客户端的 `id` 都换成渠道标记，不论条目类型。条目类型包括消息、函数调用、自定义工具调用、联网搜索调用，以及以后新增的类型。标记里的渠道是这次实际回答的渠道。
- C2：流式响应里，凡是引用某条输出条目的地方，都换成同一个标记：条目新增和完成事件里条目的 `id`、各类增量和完成事件里的 `item_id`、最终完整响应里各条目的 `id`。
- C3：中台把聊天格式、Claude 格式、Gemini 格式的上游回复转成 Responses 格式时，生成的条目编号同样带标记；开了透传的渠道、走 WebSocket 的请求同样带标记。
- C4：工具调用的 `call_id`、响应本身的编号（`resp_` 开头）、条目里的其他字段不改。
- C5：带标记的编号能还原出上游返回的原值，一个字节都不差；同一条条目在非流式和流式里得到的标记规则相同。

## 验收
- [ ] C1：非流式响应落在 5 号渠道，`output` 含思考记录 `rs_r`、自定义工具调用 `msg_aaa`（`call_id` `call_1`）、消息 `msg_bbb`、联网搜索调用 `ws_ccc` → 四条的 `id` 都带标记，分别读出 (5, 原值)。
- [ ] C2：流式请求，上游在条目新增、`response.custom_tool_call_input.delta`、`response.output_text.delta`、条目完成、`response.completed` 里都引用了 `msg_aaa` 或 `msg_bbb` → 客户端收到的每一处都是对应的同一个标记。
- [ ] C3：聊天格式上游转 Responses 输出的消息与函数调用条目、透传渠道的输出、WebSocket 的输出 → 条目编号都带标记，读出本次渠道。
- [ ] C4：上例中 `call_id` 仍为 `call_1`，响应 `id` 仍为上游原值，条目其他字段与上游一致。
- [ ] C5：编号含 `+`、`/`、`=`、`-`、`_` 的条目 → 还原值与原值逐字节相同。

## 验证路径
1. 用 Codex 请求一个 deepseek 渠道并让它调用工具 → 抓到的响应里工具调用和消息的编号都是标记，`call_id` 不变。
2. 流式请求同一渠道 → 每个事件里同一条目的编号一致。

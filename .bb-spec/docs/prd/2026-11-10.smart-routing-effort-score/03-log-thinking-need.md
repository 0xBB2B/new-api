# 日志显示思考需求

## 用户故事
### P1：作为管理员，我想在日志详情里看到每次的思考需求，以便判断分数和发出的力度是否合理

**用例（主路径）**
- 场景：员工的一条消息进了困难档，思考需求是 0.72，上游收到 xhigh。
- 操作：管理员在使用日志里打开这条请求的详情。
- 预期：智能路由区块的「打分标签」行写着「任务类型: 分析或排查 · 要想多深: 高 · 思考需求: 0.72 · 工作量: 几步 · 出错代价: 低 · 工作类型: 代码 · 可信度: 0.82 · 用户反馈: 中性」；「思考力度」行仍写「xhigh（跟随打分）」。

**用例（边界 / 异常）**
- 场景：打分返回的思考需求是 1.5，其他标签正常。
- 预期：「打分标签」行里写「思考需求: 无效」，「思考力度」行写「xhigh（跟随打分）」。
- 场景：管理员打开这次改动上线前的日志。
- 预期：「打分标签」行里没有「思考需求」这一项，其余内容和以前一样。

## 约束
- C1：打分成功且思考需求有效 → 「打分标签」行在「要想多深」后面加一项「思考需求: <值>」，值保留两位小数，按界面语言格式化，和「可信度」的写法一样。英文界面写 "Thinking need: <值>"。
- C2：思考需求无效、其他标签正常 → 这一项写「思考需求: 无效」，英文界面写 "Thinking need: Invalid"。
- C3：日志里没有记录思考需求（改动上线前的日志）→ 不显示这一项。
- C4：工具结果续跑、打分失败的日志，和现在一样不显示「打分标签」行。

## 验收
- [ ] C1：打开思考需求为 0.72 的日志 → 中文界面「打分标签」在「要想多深: 高」后面是「思考需求: 0.72」；英文界面是 "Thinking need: 0.72"；思考需求为 0.5 时显示 0.50。
- [ ] C2：打开思考需求为 1.5 的日志 → 显示「思考需求: 无效」，英文界面显示 "Thinking need: Invalid"。
- [ ] C3：打开改动上线前写入的日志 → 「打分标签」行里没有「思考需求」，其余各项和改动前一样。
- [ ] C4：打开工具结果续跑和打分超时的日志 → 都没有「打分标签」行。

## 验证路径
1. 用桩打分模型返回思考需求 0.72 发一条请求 → 日志详情的「打分标签」行里有「思考需求: 0.72」。
2. 返回思考需求 1.5 再发一条 → 日志详情里显示「思考需求: 无效」。
3. 打开一条改动前的旧日志 → 没有「思考需求」这一项。

# 打分给出思考需求

## 用户故事
### P0：作为管理员，我想让打分模型给出一个 0～1 的「思考需求」，以便力度能按问题需要多少思考来定

**用例（主路径）**
- 场景：员工用 auto-gpt 发了一条新消息："把这段 SQL 改成按月汇总"。
- 操作：new-api 调用打分模型。
- 预期：发给打分模型的说明里，除了现有 7 个字段，还要求返回「思考需求」，并写明它的含义：0～1 的数，表示最新一条请求需要多少思考；目标越模糊、问题越难，数越大；目标越明确、越简单，数越小。打分模型返回 `0.25`，这个值被接受，用来定力度。

**用例（边界 / 异常）**
- 场景：打分模型返回的思考需求是 `1.5`，其他 7 个字段都合格，要想多深是高。
- 预期：请求照常进困难档，选档原因和不带这个字段时一样，不标「打分失败」；只有力度按"思考需求无效"处理。
- 场景：打分模型漏了思考需求，或者返回的是字符串 `"0.5"`。
- 预期：同上，按"思考需求无效"处理。
- 场景：思考需求是 `0.4`，但工作量写成了 `lots`（不在可选值里）。
- 预期：和现在一样，整次打分算格式不对，走默认档。

### P0：作为员工，我想让选哪个模型不因为这次改动而变化，以便同样的问题还是交给同样的模型

**用例（主路径）**
- 场景：同一条消息打两次分，7 个标签完全一样，思考需求一次是 0，一次是 1。
- 预期：两次进的是同一档，选档原因也一样。

## 约束
- C1：打分请求要求模型额外返回「思考需求」，并写明含义：0～1 的数，表示最新一条请求需要多少思考；目标越模糊、问题越难，数越大；目标越明确、越简单，数越小。
- C2：思考需求是 0～1 之间（含 0 和 1）的 JSON 数字 → 有效；缺失、不是数字（包括字符串形式的数字）、小于 0 或大于 1 → 无效。
- C3：思考需求无效、其他 7 个字段都合格 → 不算打分失败；选档、降档保护、转顾问的判断照常按这 7 个标签进行。
- C4：其他 7 个字段里任意一个不合格 → 和现在一样，整次打分算格式不对，不论思考需求是否有效。
- C5：选档规则不看思考需求：7 个标签相同时，思考需求取任何值，选中的档位和选档原因都相同。

## 验收
- [ ] C1：抓发给打分模型的请求 → 说明里有「思考需求」这一项，写着 0～1、目标越模糊和问题越难数越大、目标越明确和越简单数越小。
- [ ] C2：打分返回思考需求 0、0.5、1 → 都按有效处理；返回 -0.1、1.5、`"0.5"`、`null`，或者不返回 → 都按无效处理。
- [ ] C3：思考需求为 1.5，其他标签是"任务类型：规划或设计"→ 进困难档，选档原因是「任务类型=规划或设计」，不是「打分结果格式不对，使用默认档」。
- [ ] C4：思考需求为 0.4、工作量为 `lots` → 走默认档，选档原因是「打分结果格式不对，使用默认档」。
- [ ] C5：同一组 7 个标签，思考需求分别为 0 和 1 → 两次选中的档位和选档原因都相同。

## 验证路径
1. 用桩打分模型返回"任务类型：闲聊或简单问答、要想多深：低、工作量：一步、思考需求：0.1"，消息很短 → 进简单档。
2. 只把思考需求改成 0.9 → 仍进简单档。
3. 把思考需求改成 1.5 → 仍进简单档，不标「打分失败」。
4. 把工作量改成 `lots` → 走默认档，标「打分结果格式不对，使用默认档」。

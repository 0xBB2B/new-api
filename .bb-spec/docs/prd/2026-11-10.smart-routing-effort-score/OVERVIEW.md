# 跟随打分按思考需求选力度

## 背景与问题
档位的思考力度设成「跟随打分」时，力度取自打分标签「要想多深」。这个标签只有低、中、高三种值，分别对应 low、medium、high，再限制在管理员设的最低～最高之间。结果是：
- 管理员把范围设得再大，打分正常时也发不出 xhigh、max。例如「跟随打分 low～max」最多只发 high；只有打分失败时才会用到最高档。
- 「要想多深」只看问题难不难，不看目标是否明确。目标说得很清楚的简单任务，也可能被判成要多想，多花了钱和时间。
- 「要想多深」同时还决定选哪一档模型（高进困难档，低是进简单档的条件之一）。想单独调力度，就会连带改掉选模型。

## 目标
- 打分模型每次额外给出一个 0～1 的「思考需求」：目标越模糊、问题越难，数越大；目标越明确、越简单，数越小。
- 「跟随打分」按「思考需求」在档位的最低～最高范围里、目标模型支持的档位中按比例选力度，范围里每一档都可能用到。
- 选模型的规则完全不变。
- 管理员能在使用日志里看到每次的「思考需求」，用来判断分数是否合理。

## 非目标
- 选档规则不改。「要想多深」标签保留，只用来选档，不再影响力度。
- 「不覆盖」「固定」两种力度方式、顾问的力度、打分模型自己的思考力度都不改。
- 档位配置不加新设置项，最低～最高两个下拉框不变，已保存的配置不用迁移。
- 不做「思考需求」的统计页面，分布从使用日志里看。
- 打分请求的计费方式不改。

## 整体验证路径
1. 管理员把 auto-gpt 困难档（gpt-5.6-sol）设成「跟随打分 medium～xhigh」，鼠标移到「思考力度」旁的 ⓘ → 说明里写着按「思考需求」按比例选档。
2. 用桩打分模型让三条被分到困难档的用户新消息依次返回思考需求 0.30、0.50、0.72 → 上游依次收到 medium、high、xhigh。
3. 打开这三条请求的日志详情 → 「打分标签」里依次显示「思考需求: 0.30」「思考需求: 0.50」「思考需求: 0.72」。
4. 让打分返回的思考需求是 1.5，其他标签正常（要想多深：高）→ 请求照常进困难档、不标「打分失败」；上游收到 xhigh；日志的打分标签里显示「思考需求: 无效」。
5. 打开改动上线前的旧日志 → 打分标签里没有「思考需求」这一项，其他内容和以前一样。

## 决策记录
- **新增一个字段管力度，「要想多深」只管选档**：用户 2026-11-10 决定。「要想多深」现在既决定选哪一档（`service/smartroute/rules.go:135`、`141`），又决定力度（`service/smartroute/effort.go:40-49`）。被否决的做法：直接把「要想多深」换成 0～1 的数，再把选档规则改成按阈值判断（如 ≥0.7 进困难档）。那样会顺带改掉选模型的行为，这次只想改力度。
- **一个数同时包含"目标是否明确"和"难不难"**：用户 2026-11-10 确认。目标清楚但很难的问题（如"证明这段算法是 O(n log n)"）照样要深想，只看明确程度会让它想得太少。所以这个数定义成"需要多少思考"，判断依据同时写明确程度和难度，只输出一个数。被否决的叫法：「目标清晰度」。数越大反而越模糊，字面意思和数值方向相反，容易读反。
- **先取范围里模型支持的档，再平均分段（方案 A）**：用户 2026-11-10 选定。这样每个分数都落在模型真能用的档上，每一档分到的区间一样宽。被否决的方案 B：先在七档里按比例选，再换到模型支持的最近一档。模型支持的档稀疏时（如 glm-5.3 只支持 low、high、max），几段会挤到同一档，比例不均匀。
- **范围里一档模型支持的都没有时，先在范围的七档里按比例选，再换到最近一档**：用户 2026-11-10 选定。这和现有的换档规则一致，日志照常写降档或升档。配置页的下拉框只列模型支持的档，所以这种情况只会在保存之后、管理员把模型能力改小时出现。被否决的做法：直接用模型支持的最高档。那样可能超出管理员设的成本上限。
- **打分失败或思考需求无效时取范围里最高的一档**：沿用 `2026-11-05.smart-routing-effort` 的理由。没有分数可参考时宁可多想，成本上限仍由「最高」控制。
- **思考需求无效只影响力度，不算打分失败**：用户 2026-11-10 选定。被否决的做法：和其他 7 个字段一样，一个不对就整次作废、改走默认档。那样新字段出错会让走默认档的次数变多，违背"选档行为不变"。
- **日志里显示在「打分标签」行，无效时写「无效」**：用户 2026-11-10 在原型确认时选定。标签都在一行，管理员能拿「思考需求」和「要想多深」对照。写「无效」能让管理员看出力度为什么是最高档；不写的话会以为打分正常。被否决的做法：把分数写进「思考力度」行，如「xhigh（跟随打分 0.72）」。
- **界面叫「思考需求」，英文 Thinking need**：用户 2026-11-10 选定，和「要想多深」「思考力度」都不重名。
- **推翻的旧约束**：`2026-11-05.smart-routing-effort` 中 01-tier-effort 的 C4（「跟随打分」按「要想多深」低、中、高对应 low、medium、high），以及 C5 里"把握不足时按「要想多深」计算"那一句。其余约束（失败用最高、续跑沿用、按能力换档、不支持思考时去掉参数）不变。
- **有一个风险，这是推测，没有验证**：模型给连续分数时，结果可能扎堆在几个值附近，按比例分档的效果会打折扣。验证办法是上线后在使用日志里看「思考需求」的分布。
- **质疑结论**：值得做。三级标签用不满七档力度，现有功能里也没有能单独按"目标是否明确"调力度的办法。

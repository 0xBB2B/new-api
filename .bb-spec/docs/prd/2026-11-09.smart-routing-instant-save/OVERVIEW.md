# 智能路由改完立即保存

## 背景与问题
现在管理员在智能路由页添加、编辑、删除虚拟模型，或者覆盖、恢复模型思考能力，都只改了页面上的草稿。要再点一次页面右上角的「保存更改」，改动才真正生效。

管理员在弹窗里点了「保存」，弹窗关了、表格也变了，很容易以为已经生效。如果忘了点「保存更改」就刷新或离开页面，改动就丢了。JSON 视图也一样，改完要回到页面右上角去找保存按钮。

## 目标
- 在可视化视图里，每个改配置的操作确认后立即生效，不用再点第二个按钮。
- JSON 视图里的改动由 JSON 框下方的「保存」按钮提交，有没有改动一眼能看出来。
- 有没保存的 JSON 改动时，切回可视化前先问管理员要不要放弃，不会悄悄丢掉，也不会悄悄提交。

## 非目标
- 不改后台保存接口和检查规则。添加、编辑时的逐项检查，JSON 保存时的检查，都和现在一样。
- 不改系统设置里其他分区的保存方式，它们仍然用页面右上角的保存按钮。
- 不给「恢复内置」加确认框。
- 不处理刷新、关闭页面时 JSON 视图里还没保存的改动。
- 不改全局样式。DESIGN.md 里记的 15 处不达标项照现状保留。

## 依赖与交付顺序
01 → 02。01 去掉页面右上角的按钮后，JSON 视图要靠 02 的按钮才能保存，所以两个子需求要一起上线。

## 整体验证路径
1. 管理员打开「系统设置 → 请求策略 → 智能路由」→ 页面标题右边没有「保存更改」按钮。
2. 编辑 auto-gpt，把困难档模型换成 gpt-5.5，点弹窗里的「保存」→ 弹窗关闭，顶部提示「保存成功」；刷新页面，困难档仍是 gpt-5.5。
3. 在「模型思考能力」表里覆盖 gpt-5.6-sol，去掉 xhigh，点「保存」→ 来源变成「已覆盖」；刷新页面后不变。
4. 切到 JSON，JSON 框下方的「保存」是灰的。把困难档改回 gpt-5.6-sol →「保存」能点了；点「可视化」→ 弹出「放弃未保存的改动？」，点「取消」留在 JSON。
5. 点「保存」→ 顶部提示「保存成功」，按钮变回灰色；切回可视化，困难档是 gpt-5.6-sol；刷新页面后不变。

## 决策记录
- **去掉两步保存**：用户 2026-11-09 提出。旧 PRD（2026-11-04.smart-routing 的 05-config-page C8）写的是"和这一页其他分区一样"，决策记录里没写非要两步的理由。弹窗里点了「保存」却没生效，容易让人误会，也容易丢改动。智能路由在侧栏里单独占一页（`web/src/features/system-settings/request-policies/section-registry.tsx:53`），改它不影响其他分区。
- **每次只提交改动的那一项**：后台本来就能只保存虚拟模型配置、或只保存思考能力覆盖中的一项（`smart-routing-section.tsx:100-105`），不用新开接口。
- **JSON 视图保留显式保存**：JSON 改到一半的内容经常是不完整的，边打字边保存会不断报错，也可能把半成品写上线。
- **有没保存的 JSON 改动时切回可视化，先弹框问是否放弃**：用户 2026-11-09 选的。否掉了"拦下不让切"（想放弃改动时没有办法撤销）和"切换时自动保存"（切个标签就改了线上配置，容易误操作）。弹框还能防止下一次立即保存把没确认的 JSON 改动一起提交上去。
- **立即保存失败时，弹窗不关、填的内容保留**：用户 2026-11-09 选的。这样再点一次「保存」就能重试。否掉了"关闭弹窗、只提示错误"，那样要重新打开弹窗再填一遍。
- **JSON 的「保存」放在编辑框下方靠右**：用户 2026-11-09 在原型里选的方案 B。否掉了"放在编辑框顶栏"（方案 A）：那样按钮只有 24px 高，不显眼，还要改共用的 JSON 编辑框组件。
- **JSON 没有改动时「保存」变灰不能点**：用户 2026-11-09 选的。按钮状态本身就告诉管理员有没有没保存的改动。否掉了"能点、点了提示没有需要保存的更改"。
- **「恢复内置」点了就保存，不弹确认框**：恢复错了，再点「覆盖」就能改回来。加确认框属于新功能，这次不做。

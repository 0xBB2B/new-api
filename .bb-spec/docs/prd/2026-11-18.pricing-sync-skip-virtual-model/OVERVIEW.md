# 定价同步跳过虚拟模型名

## 背景与问题
管理员在"定价同步"里从上游拉取模型价格，和本地价格表比对后勾选要写入的条目。上游 models.dev 里有别家厂商的模型就叫 `auto`（morph 标价输入 $0.85、输出 $1.55 每百万 token；llmgateway 标价 0），它和我们智能路由里常用的虚拟模型名 `auto` 同名，于是同步结果里会出现一条 `auto`。

虚拟模型是管理员在智能路由里起的模型名，本身不对应任何渠道。客户端用它请求时，new-api 会把请求里的模型名换成选中档位的真实模型，再按真实模型的价格扣费。所以虚拟模型名的价格永远用不到。

更麻烦的是：保存智能路由设置时，系统会检查每个虚拟模型名，只要它在价格表里有条目，就判定为"真实模型名"并拒绝保存。管理员一旦在同步时勾上 `auto` 并写入，之后再保存包含 `auto` 的智能路由设置就会一直失败，而且很难想到原因是同步写进去的那条价格。

## 目标
- 定价同步的结果里不出现任何和当前虚拟模型同名的模型，管理员没有机会把它写进价格表。

## 非目标
- 清理本地价格表里已经存在的虚拟模型名价格：由管理员在价格设置里手动删除。
- 在价格设置页手动给虚拟模型名填价格时拦截。
- 在同步结果里提示"已跳过哪些虚拟模型"。

## 依赖与交付顺序
单一子需求，无依赖。

## 整体验证路径
1. 在智能路由里配置虚拟模型 `auto` 并保存成功。
2. 在定价同步里选 models.dev 作为上游，分别在勾选和不勾选"包含无变化的模型"时拉取 → 结果里都没有 `auto`，其他模型照常出现。
3. 再次保存智能路由设置 → 保存成功。

## 决策记录
- 跳过范围选"同步结果里完全不出现"，否决"照常列出但禁止勾选"：只要还在可勾选的列表里就可能被写入；禁止勾选还要改界面，收益不抵成本。
- 同名按完全一致判断，大小写也必须一样：智能路由匹配请求时就是按完全一致比较模型名，`Auto` 不会被当作 `auto` 路由，它的价格对真实模型仍然有用。
- 跳过时不提示管理员：虚拟模型本来就不需要价格，提示没有可操作的内容，还要改界面。
- 质疑结论：值得做。真实发生过 models.dev 带来 `auto` 的情况；不处理时，误写入会让智能路由设置无法保存，排查成本高。更便宜的替代"靠管理员自己别勾"已经失败过一次。

# 同步结果排除虚拟模型名

## 用户故事
### P0：作为管理员，我想要定价同步的结果里不出现虚拟模型名，以便不会误把用不到的价格写进价格表、导致智能路由设置保存失败

**用例（主路径）**
- 场景：管理员已在智能路由里配置了虚拟模型 `auto`，现在要从 models.dev 同步价格。models.dev 里有名为 `auto` 的模型。
- 操作：在定价同步里选 models.dev，点击拉取，不勾选"包含无变化的模型"；再勾选"包含无变化的模型"拉取一次。
- 预期：两次结果里都没有 `auto` 这一行；models.dev 里的其他模型照常出现，价格和改动前一致。

**用例（边界 / 异常）**
- 场景：本地价格表里已经有一条 `auto` 的价格（之前同步写进去的），智能路由里也有虚拟模型 `auto`。
- 操作：拉取任意一个上游的价格。
- 预期：结果里没有 `auto`，本地那条价格保持原样、不被改动。

- 场景：智能路由里有虚拟模型 `auto`，上游有名为 `Auto` 的模型。
- 操作：拉取这个上游的价格。
- 预期：`Auto` 照常出现在结果里。

- 场景：智能路由里没有任何虚拟模型。
- 操作：从 models.dev 拉取价格。
- 预期：`auto` 照常出现在结果里，和改动前一致。

## 约束
- 定价同步拉取接口返回的差异列表里，不包含任何名字和拉取时智能路由当前配置的虚拟模型名完全一致（区分大小写）的模型。
- 同一接口返回的价格列表（含"包含无变化的模型"打开时的完整列表）里，同样不包含这些模型。
- 名字只在大小写或其他字符上不同于虚拟模型名的模型，照常返回。
- 没有配置任何虚拟模型时，返回结果和改动前完全一致。
- 被跳过的模型名对应的本地价格条目不被修改或删除。
- 智能路由设置改了虚拟模型名后，下一次拉取按新名字跳过，不需要重启服务。

## 验收
- [ ] 配置虚拟模型 `auto`，上游数据含 `auto` 价格时，差异列表里没有 `auto`。
- [ ] 同样条件下打开"包含无变化的模型"，价格列表里没有 `auto`。
- [ ] 配置虚拟模型 `auto`，上游含 `Auto` 时，`Auto` 出现在结果里。
- [ ] 没有配置虚拟模型时，上游的 `auto` 出现在结果里。
- [ ] 本地价格表已有 `auto` 时拉取，结果里没有 `auto`，本地价格表里的 `auto` 条目原样保留。
- [ ] 把虚拟模型从 `auto` 改名为 `smart` 并保存后立即拉取，结果里没有 `smart`，`auto` 重新出现。

## 验证路径
1. 在智能路由里配置虚拟模型 `auto` 并保存 → 保存成功。
2. 定价同步选 models.dev 拉取 → 结果里没有 `auto`，其他模型照常出现。
3. 打开"包含无变化的模型"再拉取 → 仍然没有 `auto`。
4. 把虚拟模型改名为 `smart` 并保存，再拉取 → `auto` 出现，`smart` 不出现（如果上游有）。

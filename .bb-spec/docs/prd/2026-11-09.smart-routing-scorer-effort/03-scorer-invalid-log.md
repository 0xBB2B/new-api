# 格式不对时记下原始返回

## 用户故事
### P1：作为运维，我想在打分结果格式不对时看到模型原本返回了什么，以便判断是被截断、混进了思考内容还是答非所问

**用例（主路径）**
- 场景：auto-gpt 的打分模型返回"好的，我来分析一下这个请求……"这样一段不是 JSON 的文字。
- 操作：员工发一条新消息。
- 预期：主请求用默认档，使用日志标「打分失败」；服务器日志里有一条警告，写着虚拟模型 auto-gpt、打分模型名，以及这段原始返回。

**用例（边界 / 异常）**
- 场景：打分模型返回 2000 个字的内容。
- 预期：警告里只带前 500 个字。
- 场景：打分模型返回空内容。
- 预期：警告里写明原始返回为空。

## 约束
- C1：打分结果格式不对（解析不出 JSON，或标签取值不在规定选项里）→ 写一条服务器警告日志，包含虚拟模型名、打分模型名、格式不对的原因、原始返回；原始返回超过 500 个字时只取前 500 个字，为空时写明为空。
- C2：这条警告只写服务器日志，不写进使用日志，也不返回给客户端。
- C3：打分成功、超时、上游报错时不写这条警告。

## 验收
- [ ] C1：打分模型返回非 JSON 文字 → 服务器日志有一条警告，含 auto-gpt、打分模型名、原因和原始返回；返回 2000 字 → 警告里的原始返回正好是前 500 个字；返回空内容 → 警告写明为空。
- [ ] C2：同一次请求的使用日志和客户端响应里都没有原始返回的内容。
- [ ] C3：打分成功、超时、上游报错各一次 → 服务器日志里都没有这条格式不对的警告。

## 验证路径
1. 用一个会返回闲聊文字的模型当打分模型，发一条新消息 → 主请求标「打分失败」，服务器日志出现格式不对的警告和原始返回。
2. 换回正常的打分模型再发一条 → 没有这条警告。

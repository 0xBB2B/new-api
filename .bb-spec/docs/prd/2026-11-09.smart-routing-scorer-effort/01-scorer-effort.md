# 打分思考力度

## 用户故事
### P0：作为管理员，我想给打分模型选思考力度，以便会思考的打分模型也能在输出里写完标签

**用例（主路径）**
- 场景：auto-gpt 的打分模型是 deepseek-v4.1-flash，挂在 OpenAI 兼容渠道上；「模型思考能力」里已把它覆盖成支持 none、low、high、max。
- 操作：管理员编辑 auto-gpt，在「打分」页签的「思考力度」下拉里选 none，保存，再点「保存更改」；员工随后发"帮我规划下季度的招聘方案"。
- 预期：上游收到的打分请求里 `reasoning_effort` 是 `none`，没有 `max_tokens`；打分返回完整标签，主请求落到困难档，不标「打分失败」；左栏「打分」页签小字写「deepseek-v4.1-flash · none」。

**用例（主路径）**
- 场景：auto-gpt 的打分模型是 gpt-5.6-luna，思考力度留空。
- 操作：员工发一条新消息。
- 预期：上游收到的打分请求里没有任何思考参数，也没有输出长度上限；左栏「打分」页签小字写「gpt-5.6-luna · 模型默认」。

**用例（边界 / 异常）**
- 场景：打分思考力度选的是 low，管理员随后把打分模型换成 gpt-4.1（能力表写明不支持思考）。
- 预期：「思考力度」一行变成灰字「该模型不支持思考力度，请求时不发送思考参数」，原来选的 low 被清空；保存后打分请求里没有思考参数；页签小字写「gpt-4.1 · 不支持思考」。
- 场景：打分思考力度存的是 high，管理员在「模型思考能力」里把打分模型覆盖成只支持 none、low。
- 预期：打分请求发出前把 high 换成最接近的 low。
- 场景：打分模型走 Codex 渠道（只支持 Responses 接口），思考力度留空。
- 预期：上游收到的打分请求里没有 `reasoning` 字段。

## 约束
- C1：「打分」页签在「打分模型」下面新增一行「思考力度」，是单选下拉；第一项「不设置（模型默认）」，其余只列打分模型在「模型思考能力」里支持的档位，按 none、minimal、low、medium、high、xhigh、max 的顺序。
- C2：打分模型「能力未确认」时，下拉只有「不设置（模型默认）」和 low、medium、high，行末显示黄色小标签「能力未确认」，悬停提示「内置能力表里没有这个模型，可在「模型思考能力」里补充」。
- C3：打分模型不支持思考时，「思考力度」一行换成灰字「该模型不支持思考力度，请求时不发送思考参数」，没有下拉；之前选的档位被清空。
- C4：思考能力表加载失败时，下拉不能点，行末红字「思考能力加载失败」；还没选打分模型时，下拉不能点，显示「不设置（模型默认）」。
- C5：「思考力度」旁的帮助说明写明：留空时请求里不发思考参数，由模型自己决定；选了档位而模型不支持时，发出前换成能力表里最接近的一档；打分输出不限长度，耗时由「超时」控制；下拉只列这个模型支持的档位。
- C6：左栏「打分」页签的小字：没选打分模型 → 「未设置」；模型不支持思考 → 「<模型> · 不支持思考」；思考力度留空 → 「<模型> · 模型默认」；选了档位 → 「<模型> · <档位>」。
- C7：保存时打分思考力度只能是留空或七档之一，其他值 → 保存被拦下，「思考力度」一行显示「请选择有效的思考力度」。
- C8：打分请求的思考参数：
  - 留空 → 不发任何思考参数，Codex 渠道也一样；
  - 选了档位 → 先按打分模型的思考能力换档（规则和档位相同：换成支持的档位里最接近的一档，上下一样近取更高的一档），再发给上游，Chat 格式写在 `reasoning_effort`，Responses 格式（Codex 渠道）写在 `reasoning.effort`，渠道再按自己的协议转换；
  - 打分模型不支持思考 → 不发任何思考参数。
- C9：打分请求不设输出长度上限：Chat 格式不带 `max_tokens` / `max_completion_tokens`，Responses 格式不带 `max_output_tokens`。
- C10：已有配置里没有打分思考力度这一项时，按留空处理。
- C11：本子需求新增的界面文字都有 en、zh、zh-TW、fr、ru、ja、vi 七种语言的翻译。

## 验收

- [ ] C2：打分模型选 deepseek-v4.1-flash（未覆盖）→ 下拉只有「不设置（模型默认）」、low、medium、high，行末有「能力未确认」标签，悬停提示文字正确。
- [ ] C3：思考力度选 low 后把打分模型换成 gpt-4.1 → 出现灰字说明、没有下拉；保存后配置 JSON 里打分思考力度为空。
- [ ] C4：让能力表接口返回错误 → 下拉不能点，行末红字「思考能力加载失败」；新建虚拟模型、还没选打分模型 → 下拉不能点，显示「不设置（模型默认）」。
- [ ] C5：悬停「思考力度」旁的 ⓘ → 显示的说明包含留空不发、换成最接近一档、输出不限长度由超时控制、只列支持的档位四点。
- [ ] C6：四种情况下左栏「打分」页签小字分别是「未设置」「gpt-4.1 · 不支持思考」「gpt-5.6-luna · 模型默认」「gpt-5.6-luna · low」。
- [ ] C7：直接调保存接口，把打分思考力度设成 `ultra` → 返回校验错误，字段指向打分思考力度，提示「请选择有效的思考力度」。
- [ ] C8：截获上游收到的打分请求：留空 → Chat 和 Codex 渠道都没有思考参数；选 none（模型支持 none）→ Chat 请求 `reasoning_effort` 为 `none`；Codex 渠道选 low → `reasoning.effort` 为 `low`；能力只有 none、low 而选了 high → 实际发 low；打分模型为 gpt-4.1 → 没有思考参数。
- [ ] C9：截获上游收到的打分请求 → Chat 格式里没有 `max_tokens` 和 `max_completion_tokens`，Responses 格式里没有 `max_output_tokens`。
- [ ] C10：用一份没有打分思考力度字段的旧配置启动 → 打开编辑弹窗显示「不设置（模型默认）」，打分请求里没有思考参数。
- [ ] C11：切换七种界面语言 → 新增文字都有翻译。

## 验证路径
1. 在「模型思考能力」里把 deepseek-v4.1-flash 覆盖成支持 none、low、high、max → 编辑 auto-gpt，「打分」页签思考力度选 none，保存并「保存更改」→ 页签小字写「deepseek-v4.1-flash · none」。
2. 员工发一条新消息 → 上游收到的打分请求有 `reasoning_effort: none`、没有 `max_tokens`；打分消费记录的输出 token 远小于 300；主请求不标「打分失败」。
3. 把思考力度改回留空 → 上游收到的打分请求里没有思考参数。

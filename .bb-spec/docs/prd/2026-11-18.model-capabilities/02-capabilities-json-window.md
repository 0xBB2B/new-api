# 能力配置 JSON 窗口

## 用户故事
### P0：作为管理员，我想把全部模型的能力配置看成一段 JSON 并能整体替换保存，以便新模型发布时一次贴进去

**用例（主路径）**
- 场景：模型管理里 `gpt-6.2-sol`、`qwen4-max` 两条完全匹配记录配置过能力；新模型 `gpt-6.3-sol` 还没有记录。
- 操作：点标题右侧「能力配置 JSON」→ 编辑器里显示这两个模型的配置；在末尾加上 `"gpt-6.3-sol": {"context_length": 1050000}`，把 `gpt-6.2-sol` 的 `context_length` 改成 900000，点「预览更改」→ 点「替换保存 2 条改动」。
- 预期：预览显示「新建 1」「更新 1」「不变 1」；`gpt-6.3-sol` 一块写「模型管理里还没有这个模型，会新建一条完全匹配的记录。」；保存后窗口关闭，页面顶部提示「模型能力已保存」「新建 1 条、更新 1 条、清空 0 条记录」；模型列表里多了 `gpt-6.3-sol`。

**用例（边界 / 异常）**
- 场景：管理员只粘贴了一个新模型的配置，把原有内容全覆盖了。操作：预览。预期：其他模型都标「清空」，顶部出现提示框「有 N 个模型的能力配置会被清空」，逐个写明「<模型名> 不在 JSON 里。如果不是有意删掉的，请返回修改，把它加回去。」
- 场景：管理员 A 预览之后，管理员 B 在编辑抽屉里改了 `qwen4-max`。操作：A 点「替换保存」。预期：红色警示框「模型资料已变化，没有保存」，保存按钮换成「重新预览」；点了之后按最新数据重新对比。
- 场景：JSON 里有一个条目的档位写成 `"ultra"`。操作：预览。预期：红色警示框「有 1 个条目校验没通过，现在不能保存」，保存按钮变灰，什么都不改。

## 约束
- C1：入口。模型管理页标题右侧按钮从左到右为：同步资料、同步价格、能力配置 JSON（描边小按钮）、＋ 添加模型、⋯ 菜单。点「能力配置 JSON」打开同名窗口。
- C2：窗口头部。标题「能力配置 JSON」，说明「这里是所有模型现在的能力配置，按模型名组织，写法和 /v1/models 返回的一致。可以复制、下载，也可以直接改或者粘贴新内容后保存。」右上角关闭按钮；下面是步骤条「1. 查看和修改」「2. 预览并保存」，当前步骤高亮。
- C3：JSON 内容。形状为 `{"<模型名>": {<单个模型能力>}}`，单个模型能力的形状、可用值、`null` 与空模态数组的含义，与模型编辑抽屉 JSON 模式相同：只认 `context_length`、`top_provider.max_completion_tokens`、`architecture.input_modalities`（text、image、file、audio）、`architecture.output_modalities`（text、image、audio）、`reasoning.supported_efforts`（none、minimal、low、medium、high、xhigh、max，`[]` 表示不支持思考）；数字为 1 到 9007199254740991 的整数。
- C4：打开时列出的范围。编辑器里按模型名排序，列出所有名称规则为完全匹配、且至少配置了一项能力的记录；未配置的字段不出现。
- C5：没列进来的记录。有记录没列进 JSON 时，编辑器上方出现提示框「有 N 条记录没有列在下面」，分两类写明：
  - 不是完全匹配的记录（列出名字和规则）：「它们的名字不是具体的模型名，请在编辑抽屉里单独修改，这里保存不会动它们。」
  - 还没有配置任何能力的记录（列出名字）：「要给它配置，可以在下面加上它的名字。」
- C6：第 1 步底栏。左边一句状态：没改动时「N 个模型有能力配置」，改过后「您有未保存的更改」；右边「关闭」「下载 JSON 文件」「预览更改」。复制用编辑器工具栏的「复制」，成功后顶部提示「已复制到剪贴板」。
- C7：下载。点「下载 JSON 文件」把编辑器里当前的内容（含未保存的改动）存成文件，文件名 `model-capabilities-<YYYY-MM-DD>.json`。
- C8：第 1 步的其他状态：
  - 没改动时「预览更改」变灰。
  - 空数据（没有任何完全匹配记录配置过能力）：不显示 C5 的"还没配置"那类提示，编辑器为空并显示示例占位；底栏写「还没有模型配置过能力，可以直接粘贴 JSON」；「下载 JSON 文件」「预览更改」变灰。
  - JSON 格式错误：工具栏红色「JSON 无效」，下方红字「JSON 格式错误，改好后才能预览。」「预览更改」变灰。
  - 加载中：「加载中...」，底栏右侧两个按钮变灰。
  - 加载出错：「糟糕！出错了」「读取模型能力失败」加「重试」。
- C9：整体替换规则。保存后，每个列进 JSON 的模型能力就是 JSON 里写的样子：没写的字段、写成 `null` 的字段都清空成未配置。当前配置过能力、却不在 JSON 里的完全匹配记录，能力全部清空，记录本身保留。名称规则不是完全匹配的记录一律不改。这段规则写在编辑器下方：「保存时整体替换：保存后，每个模型的能力就是这里写的样子。没写的字段、写成 null 的字段都会被清空。从 JSON 里删掉一个模型，它的能力配置会被清空，记录本身保留。模型管理里还没有记录的模型，会自动新建一条完全匹配的记录。」
- C10：自动新建。JSON 里的模型名在模型管理里没有完全匹配记录时，保存会新建一条完全匹配记录并写入能力。这个名字当前被前缀、后缀、包含规则的记录命中时，新记录复制命中那条记录的其他资料（描述、图标、标签、厂商、接口配置、广场可见状态、是否允许同步资料），所以这个模型除能力以外的信息不变；没有被命中时，其他资料与在页面上手动新建记录的默认值相同。
- C18：JSON 里的模型名必须是 1 到 128 个字符；和一条前缀、后缀、包含规则记录同名时，这一条校验不通过，错误信息说明「这个名字已被前缀、后缀或包含规则的记录占用，请在编辑抽屉里修改那条记录」，整批不能保存。
- C11：预览。点「预览更改」时按服务器当前最新数据对比，进入第 2 步：
  - 顶部徽标：新建 N、更新 N、清空 N（红色）、不变 N；有校验错误时再加红色「校验没通过 N」。
  - 有模型会被清空时，出现提示框「有 N 个模型的能力配置会被清空」，逐个写「<模型名> 不在 JSON 里。如果不是有意删掉的，请返回修改，把它加回去。」
  - 每个模型一块：模型名加徽标（新建 / 更新 / 清空 / 不变），下面一张表「字段 / 当前值 / 更改为」，只列有变化的字段。新建的当前值都是「—」，表下写「模型管理里还没有这个模型，会新建一条完全匹配的记录。」；更新中被清空的字段「更改为」显示「清空（未配置）」；清空的模型每个已有字段都改成「清空（未配置）」，表下写「JSON 里没有这个模型，它的能力配置会被清空，记录本身保留。」；不变的不画表，只写「和现在的配置一样，不会改动。」
  - 底栏左边汇总「将新建 N 条、更新 N 条、清空 N 条记录」，右边「返回修改」「替换保存 N 条改动」（N 为新建、更新、清空之和）。
- C12：校验失败。任一条目不满足 C3 时，第 2 步出现红色警示框「有 N 个条目校验没通过，现在不能保存」「请返回修改 JSON，全部通过后再保存。」，下面一张表「校验没通过的条目（N）」列出模型和问题；「替换保存」按钮变灰。服务器对同样的输入同样拒绝，什么都不改。
- C13：保存要么全成，要么全不改。保存中两个按钮变灰，保存按钮写「正在保存...」；任何一条写入失败时，所有改动都不生效，出现红色警示框「保存失败，没有任何改动生效」加原因，可以再点一次保存。
- C14：保存时查版本。点「替换保存」时，如果预览之后有任何一条涉及的记录（会新建、更新、清空的记录，以及会被复制资料的命中记录）被改过、删除，或者有同名完全匹配记录被新建，就拒绝保存、什么都不改：红色警示框「模型资料已变化，没有保存」「预览之后，有模型的资料被改过，下面的对比已经不是最新的。请重新预览，确认最新的改动后再保存。」，底栏保存按钮换成主色「重新预览」，点了按最新数据重新对比；「返回修改」仍可用，JSON 内容保留。
- C15：保存成功。窗口关闭，模型管理页顶部提示「模型能力已保存」，副文案「新建 N 条、更新 N 条、清空 N 条记录」。
- C16：「返回修改」回到第 1 步，JSON 内容保留；「关闭」或右上角按钮关闭窗口，未保存的改动丢弃。
- C17：这个窗口的读取和保存，只有能管理模型资料的管理员可以用，权限与模型管理页的编辑相同；服务器端检查权限。

## 验收
- [ ] C1：模型管理页标题右侧按钮顺序与约束一致；页面上没有「批量导入能力」「导出能力」按钮。
- [ ] C2：窗口标题、说明、步骤条与约束一致。
- [ ] C3：JSON 里写 C3 列出的全部合法值 → 预览通过；写列表外的值、0、多余字段 → 校验没通过。
- [ ] C4：两条完全匹配记录配置过能力、一条完全匹配记录未配置 → 打开窗口只列两条，按名字排序，未配置字段不出现。
- [ ] C5：另有前缀记录 `gpt-6`、未配置记录 `glm-5.2` → 提示框按两类分别列出它们和对应说明。
- [ ] C6：底栏状态文字随有无改动变化；点工具栏「复制」→ 剪贴板内容与编辑器一致，出现「已复制到剪贴板」。
- [ ] C7：改了 JSON 不保存直接下载 → 文件名为当天日期，内容是改后的 JSON。
- [ ] C8：五种状态的显示与按钮可用性与约束一致。
- [ ] C9：JSON 里 `gpt-6.2-sol` 去掉 `architecture`、删掉 `qwen4-max` → 保存后 `gpt-6.2-sol` 的模态为未配置、`qwen4-max` 五项全为未配置且记录仍在；前缀记录 `gpt-6` 的能力不变。
- [ ] C10：新增 `gpt-6.3-sol`（被前缀记录 `gpt-6` 命中）→ 保存后新建完全匹配记录，描述、图标、标签、厂商、接口配置、广场可见状态与 `gpt-6` 相同；新增 `foo-model`（无命中）→ 新记录其他资料为默认值。
- [ ] C11：主路径预览的徽标、每块内容、清空提示框、底栏汇总与约束一致。
- [ ] C12：一个条目写 `"ultra"` → 警示框和错误表出现，保存按钮不可用；直接调用保存接口提交同样内容 → 被拒绝，所有记录不变。
- [ ] C13：模拟其中一条写入失败 → 所有记录都保持保存前的样子，界面显示「保存失败，没有任何改动生效」。
- [ ] C14：预览后另开页面修改一条涉及的记录，再点保存 → 被拒绝且什么都不改，显示约束里的文案和「重新预览」；点「重新预览」→ 对比反映最新数据。
- [ ] C15：保存成功后的提示和副文案数字与预览一致。
- [ ] C16：「返回修改」后 JSON 保留；关闭再打开 → 显示服务器当前配置。
- [ ] C18：JSON 写 `""`、129 个字符的名字、或与前缀记录 `gpt-6` 同名的 `"gpt-6"` → 预览出现对应校验错误，保存被拒，记录不变，表里没有同名记录。
- [ ] C17：没有模型管理权限的账号调用读取和保存接口 → 被拒绝。

## 验证路径
1. 准备两条配置过能力的完全匹配记录、一条前缀记录、一条未配置记录 → 打开「能力配置 JSON」，检查列出内容和提示框。
2. 复制、下载 → 内容一致，文件名正确。
3. 按主路径修改并预览 → 徽标与每块内容正确；替换保存 → 提示数字正确，记录按整体替换规则变化。
4. 再次打开，删掉一个模型并预览 → 出现清空提示框；在另一页面改一条涉及的记录后保存 → 被拒绝，重新预览后保存成功。
5. 写入非法值 → 校验没通过，什么都不改。

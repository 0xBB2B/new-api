# 模型记录上配置能力

## 用户故事
### P0：作为管理员，我想在编辑一个模型时配置它的能力，以便调用方和智能路由按真实能力使用它

**用例（主路径）**
- 场景：管理员在模型管理页（管理 → 模型，`/models/metadata`）打开 `gpt-6.2-sol` 的编辑抽屉。
- 操作：在「模型能力」分区勾选输入模态「文字」「图片」，输出模态「文字」，上下文大小填 1050000，最大输出 token 填 128000，思考等级勾选 none、low、medium、high、xhigh、max，点「保存资料」。
- 预期：抽屉关闭，页面顶部提示「模型资料已保存」；再次打开抽屉，五项都是刚填的值；切到 JSON 模式看到 `{"context_length":1050000,"top_provider":{"max_completion_tokens":128000},"architecture":{"input_modalities":["text","image"],"output_modalities":["text"]},"reasoning":{"supported_efforts":["none","low","medium","high","xhigh","max"]}}`。

**用例（边界 / 异常）**
- 场景：`gpt-4o` 确认不支持思考。操作：打开「不支持思考」开关，保存。预期：七个档位复选框变灰不能点；JSON 模式显示 `"reasoning": { "supported_efforts": [] }`。
- 场景：上下文大小误填 `-5`。操作：点保存。预期：输入框变红，下方显示「请输入大于 0 的整数」，不能保存。
- 场景：JSON 模式里把 `input_modalities` 写成 `["text","video"]`。操作：点保存。预期：编辑器下方红字「architecture.input_modalities 里有不认识的值 video，可用的值：text、image、file、audio」，不能保存。

## 约束
- C1：分区位置。模型编辑抽屉「模型资料」标签页里新增「模型能力」分区，排在「匹配规则」之后、「端点」之前；名称规则是完全匹配、前缀、包含、后缀的记录都显示这个分区。
- C2：分区头部。左边标题「模型能力」，右边一个描边小按钮：表单模式下写「JSON 模式」，JSON 模式下写「可视模式」。标题下说明：「这里填的内容会通过 /v1/models 返回给调用方。没填的项不返回。」
- C3：表单字段，从上到下：
  - 输入模态：复选框 文字（text）、图片（image）、文件（file）、音频（audio），说明「一个都不勾表示未配置。」
  - 输出模态：复选框 文字（text）、图片（image）、音频（audio），说明「一个都不勾表示未配置。」
  - 上下文大小、最大输出 token：两个输入框并排，占位文字「例如 1050000」「例如 128000」，说明「单位是 token。不填表示未配置。」
  - 思考等级：开关「不支持思考」，下面七个复选框 none、minimal、low、medium、high、xhigh、max，说明「勾选这个模型支持的档位。开关没开、一档也没勾，表示未配置。」
- C4：每一项都能处于「未配置」状态。全部不勾、输入框为空、开关关闭时可以正常保存，不报错。
- C5：打开「不支持思考」时七个档位复选框变灰、不能点；关上后恢复成打开前的勾选，其他字段不受影响。
- C6：上下文大小、最大输出 token 只接受 1 到 9007199254740991 的整数。填 0、负数、小数、非数字或超过上限时，输入框变红，显示「请输入大于 0 的整数」，不能保存。
- C7：JSON 模式。标签「能力配置」，带行号的 JSON 代码编辑器，工具栏有行列号、「JSON」/「JSON 无效」状态、复制、格式化 JSON。说明：「形状和 /v1/models 返回的一致。没写的字段表示未配置；不支持思考写 "supported_efforts": []。」
- C8：JSON 形状。只认这五个位置：`context_length`、`top_provider.max_completion_tokens`、`architecture.input_modalities`、`architecture.output_modalities`、`reasoning.supported_efforts`。未配置的字段不出现；全部未配置时显示 `{}`；不支持思考时为 `"reasoning": { "supported_efforts": [] }`。写成 `null` 或空模态数组 `[]` 的字段按未配置处理。
- C9：两种模式互相切换时内容保持一致：表单里勾的、填的，切到 JSON 后就是对应的值；JSON 里写的，切回表单就是对应的勾选和数字。
- C10：JSON 格式错误时，工具栏显示红色「JSON 无效」，编辑器下方红字「JSON 格式错误，改好后才能保存，也才能切回可视模式。」；「可视模式」按钮变灰，不能保存。
- C11：JSON 里出现不认识的值（不在 C3 列表里的模态、不在七档里的思考档位）、数字不满足 C6、或出现 C8 以外的字段时，编辑器下方逐条红字「<字段路径> 里有不认识的值 <值>，可用的值：……」（数字和多余字段写明原因），不能保存。服务器对同样的输入同样拒绝，不依赖页面检查。
- C12：思考档位、模态数组保存时去掉重复值；思考档位按 none、minimal、low、medium、high、xhigh、max 的顺序保存和显示。
- C13：保存。点「保存资料」时两个底栏按钮变灰，保存按钮变「正在保存...」；成功后抽屉关闭，页面顶部提示「模型资料已保存」；失败时底栏上方出现红色警示框写明原因，抽屉不关，已填内容不丢。
- C14：这五项能力和这条记录的其他资料一起保存；「同步官方资料」不会改动它们。

## 验收
- [ ] C1：完全匹配和前缀规则的记录打开编辑抽屉，都能在「匹配规则」和「端点」之间看到「模型能力」分区。
- [ ] C2：分区标题、模式切换按钮文字、说明文字与约束一致。
- [ ] C3：表单字段、选项、占位文字、说明文字与约束一致。
- [ ] C4：五项全部未配置时保存成功，再打开仍全部未配置，JSON 模式显示 `{}`。
- [ ] C5：先勾 low、high，再打开「不支持思考」→ 档位变灰；关上 → low、high 仍勾着；上下文大小不变。
- [ ] C6：上下文大小分别填 0、-5、1.5、abc、9007199254740992 → 都提示「请输入大于 0 的整数」且不能保存；填 9007199254740991 → 能保存。
- [ ] C7：JSON 模式标签、工具栏、说明与约束一致。
- [ ] C8：主路径保存后 JSON 模式显示的内容与用例一致；只配了上下文大小时 JSON 里只有 `context_length`；`"input_modalities": []` 保存后按未配置显示。
- [ ] C9：表单配好五项 → 切 JSON → 内容对应；在 JSON 里改 `context_length` → 切回表单 → 输入框显示新值。
- [ ] C10：JSON 少一个右括号 → 显示「JSON 无效」和错误说明，「可视模式」按钮和保存都不可用。
- [ ] C11：JSON 写 `"video"` 模态、`"ultra"` 档位、`"foo": 1` 多余字段 → 各自显示错误且不能保存；直接调用保存接口提交同样内容 → 服务器拒绝，记录不变。
- [ ] C12：JSON 写 `"supported_efforts": ["high","low","high"]` → 保存后显示为 low、high。
- [ ] C13：保存中按钮状态、成功提示、失败警示框与约束一致；失败后抽屉里的内容还在。
- [ ] C14：给配置过能力的模型执行「同步官方资料」→ 五项能力不变。

## 验证路径
1. 打开模型管理页，编辑 `gpt-6.2-sol`，按主路径填好并保存 → 看到「模型资料已保存」。
2. 重新打开 → 五项与填写一致；切 JSON 模式 → 内容与主路径预期一致。
3. 打开「不支持思考」→ 档位变灰；保存后 JSON 为 `"supported_efforts": []`。
4. 依次输入 C6、C10、C11 的错误值 → 各自报错且不能保存。

# 日志里的思考力度

## 用户故事
### P0：作为员工和管理员，我想看到每次请求实际用了什么思考力度、怎么来的，以便明白扣费和回答质量的差别

**用例（主路径）**
- 场景：auto-gpt 困难档是「跟随打分 medium～xhigh」，员工的消息「要想多深：高」。
- 操作：打开这条记录的日志详情。
- 预期：「智能路由」块里「档位」下面一行「思考力度」写「high（跟随打分）」。

**用例（边界 / 异常）**
- 场景：auto-gpt 简单档「不覆盖」，客户端传 xhigh，gpt-5.4-mini 最高 high。
- 预期：「思考力度」写「high（不覆盖，由 xhigh 降档）」。
- 场景：auto-chat 简单档是 gpt-4.1（不支持思考）的工具结果续跑。
- 预期：「思考力度」写「未发送（模型不支持思考）」。

## 约束
- C1：经过智能路由的主请求，详情弹窗「智能路由」块在「档位」下面新增一行「思考力度」，写实际发给上游的力度，括号里写来源：
  - 跟随打分 →「<力度>（跟随打分）」；
  - 固定 →「<力度>（固定）」；
  - 不覆盖或顾问、客户端带了值 →「<力度>（不覆盖，客户端传入）」；
  - 发出前按模型能力换了档位 → 括号里在来源后面加「，由 <原力度> 降档」，例如「high（跟随打分，由 xhigh 降档）」「high（不覆盖，由 xhigh 降档）」；
  - 模型不支持思考、去掉了思考参数 →「未发送（模型不支持思考）」；
  - 不覆盖、客户端没带值 →「未发送（客户端未指定）」。
- C2：工具结果续跑、压缩请求同样显示这一行，取值按续跑时实际发出的力度。
- C3：打分记录的详情不显示这一行。
- C4：一期写入、没有思考力度信息的旧日志，详情里不显示这一行，其他内容不变。
- C5：用户和管理员看到的这一行相同；新增文字都有七种界面语言的翻译。

## 验收
- [ ] C1：分别构造跟随打分、固定、不覆盖带值、顾问带值、降档、不支持思考、不覆盖不带值七种请求 → 详情里「思考力度」一行依次是约束里的七种写法。
- [ ] C2：一轮 high 之后的工具结果续跑 → 详情写「high（跟随打分）」，且没有打分标签和打分记录。
- [ ] C3：打开打分记录的详情 → 没有「思考力度」一行。
- [ ] C4：打开升级前写入的智能路由日志 → 没有「思考力度」一行，页面不报错。
- [ ] C5：普通用户和管理员打开同一条日志 → 「思考力度」一行内容相同；切换七种语言都有翻译。

## 验证路径
1. 按「档位思考力度」的验证路径跑出几种请求 → 打开每条日志详情，核对「思考力度」一行的值和来源。
2. 打开打分记录和升级前的旧日志 → 都没有这一行。
3. 拿实际详情弹窗和确认过的预览逐个状态对比。

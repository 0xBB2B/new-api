# 档位思考力度

## 用户故事
### P0：作为管理员，我想让困难档的思考力度跟着问题难度变，以便难题想得深、一般问题不多花钱

**用例（主路径）**
- 场景：auto-gpt 的困难档是 gpt-5.6-sol（支持 low / medium / high / xhigh），思考力度选「跟随打分」，最低 medium、最高 xhigh。
- 操作：员工发了三条都被分到困难档的消息，打分的「要想多深」依次是高、中、低。
- 预期：发往上游的思考力度依次是 high、medium、medium（low 被抬到最低 medium）。

**用例（边界 / 异常）**
- 场景：同一个困难档，打分超时。
- 预期：用默认档；如果默认档也是跟随打分，用它的最高档。被分到困难档的工具结果续跑请求沿用本轮算出的力度。
- 场景：简单档 gpt-5.4-mini（最高支持 high）选「不覆盖」，客户端传了 xhigh。
- 预期：发往上游的是 high。
- 场景：简单档选了 gpt-4.1（不支持思考），客户端传了 reasoning_effort=low。
- 预期：发往上游的请求里没有任何思考力度参数。

### P0：作为员工，我想让请求不因为思考力度配错而报错，以便用虚拟模型和用真实模型一样稳

**用例（主路径）**
- 场景：管理员把 gpt-5.6-sol 的能力覆盖成只支持 low / medium / high，auto-gpt 困难档还存着「跟随打分 medium～xhigh」。
- 操作：员工的消息被分到困难档，打分失败。
- 预期：本该发 xhigh，实际发 high，请求正常返回。

## 约束
- C1：每个档位的思考力度有三种方式：「不覆盖」「固定」「跟随打分」，新建档位默认「不覆盖」。力度的可选值是 none、minimal、low、medium、high、xhigh、max 七档，从低到高排列。
- C2：「不覆盖」→ 发往上游的力度是客户端请求里带的值；客户端没带就不加。
- C3：「固定」→ 管理员选一个值，发往上游的力度是这个值，覆盖客户端带的值。
- C4：「跟随打分」→ 管理员选最低和最高两个值（最低不能高于最高）。用户新消息按打分标签「要想多深」取值：低→low，中→medium，高→high；再限制在最低～最高之间（低于最低取最低，高于最高取最高）。结果覆盖客户端带的值。
- C5：「跟随打分」时，打分失败（超时、上游报错、返回内容格式不对）→ 用这一档的最高值。打分把握不足而用默认档时，「要想多深」照样有值，按 C4 计算。
- C6：工具结果续跑、Responses 压缩请求不打分 → 力度沿用这段对话本轮用户新消息最终发出的力度；会话没有记录时，「跟随打分」按 C5 用最高值，「固定」用固定值，「不覆盖」用客户端的值。
- C7：按 C2~C6 算出的力度，模型不支持时，发出前换成模型支持的档位里最接近的一档；上下一样近时取更高的那档。模型支持哪几档按「模型思考能力」的结果（内置或管理员覆盖）。
- C8：档位模型不支持思考 → 不论哪种方式，发往上游的请求里都去掉思考力度参数（Responses 的 `reasoning.effort`、Chat Completions 的 `reasoning_effort`、Anthropic 格式的思考设置）。
- C9：顾问接手的这一轮，思考力度照旧用客户端带的值，不按 C7 改写。
- C10：一期已保存的档位力度原样迁移：「不覆盖」仍是不覆盖；low / medium / high 变成「固定」加同样的值。迁移后不需要管理员重新保存。
- C11：三种请求格式（Responses、Chat Completions、Anthropic）都按 C2~C9 处理。

## 验收
- [ ] C1：新建虚拟模型 → 三档思考力度默认都是「不覆盖」；后台接受七档里任一值，七档以外的值保存时报错。
- [ ] C2：「不覆盖」，客户端带 medium → 上游收到 medium；客户端不带 → 上游请求里没有力度参数。
- [ ] C3：「固定 medium」，客户端带 high → 上游收到 medium。
- [ ] C4：「跟随打分 medium～xhigh」，模型支持 low～xhigh，「要想多深」为 高 / 中 / 低 → 上游依次收到 high / medium / medium；最低高于最高时保存报错。
- [ ] C5：「跟随打分 medium～xhigh」，打分超时或格式不对 → 上游收到 xhigh；把握不足、「要想多深：低」→ 上游收到 medium。
- [ ] C6：一轮用户新消息发了 high，之后同一会话的工具结果续跑和压缩请求 → 上游收到 high；新会话第一条就是工具结果续跑、「跟随打分 medium～xhigh」→ 上游收到 xhigh。
- [ ] C7：「不覆盖」，客户端带 xhigh，模型最高 high → 上游收到 high；模型只支持 low 和 high、算出 medium → 上游收到 high；模型被覆盖成只到 high、「跟随打分」打分失败 → 上游收到 high。
- [ ] C8：档位模型不支持思考，客户端带 low，三种格式各发一次 → 上游请求里都没有思考力度参数。
- [ ] C9：交给顾问的一轮，客户端带 low → 上游收到 low，即使顾问模型不支持 low 也不改写。
- [ ] C10：用一期保存的配置启动（困难档 effort=high）→ 配置页显示「固定 high」，请求按固定 high 发送。
- [ ] C11：C2~C9 的用例分别用 Responses、Chat Completions、Anthropic 格式各跑一次，结果相同。

## 验证路径
1. 配置 auto-gpt 困难档「跟随打分 medium～xhigh」，用桩打分模型分别返回「要想多深」高、中、低 → 抓上游请求，力度依次是 high、medium、medium。
2. 让打分超时 → 上游力度 xhigh；接着发同一会话的工具结果续跑 → 上游力度仍是 xhigh。
3. 把 gpt-5.6-sol 覆盖成只到 high → 再让打分超时，上游力度变成 high。
4. 简单档换成 gpt-4.1，客户端带 reasoning_effort → 上游请求里没有这个参数。
